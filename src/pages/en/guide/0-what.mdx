## The short version

pstack is a pack of <Term k="技能" text="skills" /> that goes into your AI coding tool. Once it's installed, the AI writes code by a senior engineer's rules: <mark><strong>understand first, then act, then show the evidence.</strong></mark>

It isn't a new model or a new app. It's a set of instruction files written for the AI, and they live inside the Claude Code, Cursor, or Codex you already use. The model stays the same. What changes is the order it works in and the bar it has to clear.

## What problems it solves

If you've written code with AI, you've probably seen some of these:

- **Changing code it hasn't understood.** It dives straight in and edits a spot that looks right but isn't.
- **Treating only the symptom.** It sees duplicate data and adds a dedupe where the data is displayed. The bug that creates the duplicates is still there.
- **Saying "done" without proof.** "Fixed, should be fine now." You run it, and it's still broken.
- **Changes that keep growing.** A pile of compatibility shims, comments, and defensive checks nobody needs. They're tiring to review, and the next bug hides in them.

pstack's author, poteto, has written code at the scale of millions of lines at Meta, Netflix, and Cursor, and works on React Compiler on the React core team. Their stance is blunt: **there's too much AI slop code; to go fast, you first have to go deep.** pstack is the setup they use every day in Cursor to write high-quality code, later open-sourced.

## What's inside

| Thing | How many | In plain words |
| --- | --- | --- |
| Main entry `/poteto-mode` | 1 | You state the goal, it plans everything. As a beginner, this is the only one you need to remember. |
| <Term k="剧本" text="Playbooks" /> | 23 | Fix a bug, add a feature, refactor, chase performance... one standard approach per kind of task. |
| Skills | 34 | `/how` explains code, `/interrogate` brings in critics to poke holes, `/bro` puts things in plain words... see the [skills list](/en/skills/). |
| <Term k="原则" text="Principles" /> | 24 | "subtract before you add", "prove it works", "fix root causes"... each one has a name, and saying the name steers the AI back on track. |
| Subagents | 2 | `poteto-agent` (helpers it sends out follow the same rules) and Comment Sicko (reviews comments, nothing else). |

You don't need to learn all of this. Day to day, just type `/poteto-mode`. It calls in the other skills when it needs them.

## What you get from it

- **Less code, but better code.** The first principle is "delete what you can, solve the problem with the smallest change." It isn't chasing line count. Quite the opposite.
- **No more "should be fixed now."** Every task has to end with real evidence: run real commands, read real data, click through the real UI.
- **Confidence to run several AIs at once.** Every AI follows the same rules and works in its own directory, so you can run them in parallel without watching each one. The author calls this "fearless parallelism."
- **It gets smoother the more you use it.** Make the same mistake twice and it gets blocked at the root (`/correct`). Once you know it well, generate a working mode of your own (`/automate-me`).

<Callout type="warn" title="The cost, stated plainly">
pstack sends out extra subagents and has several models review each other, so **the same job is slower and uses more tokens**. That's the price of being rigorous. Skip it for small changes. For ways to save, see [Controlling cost](/en/howto/cost/).
</Callout>

## What to have ready before you start

- **An AI coding tool**: any one of Claude Code, Cursor, or Codex (OpenCode and Pi work too). It needs to be able to read and write your code and run commands. <u>A chat-only AI in the browser won't work</u>.
- **A model you can use**: a paid subscription to the tool, or an API key. pstack defaults to a fairly high reasoning level.
- **A real project, ideally in Git**: most playbooks create a <Term k="worktree" />, make commits, and open a <Term k="PR" />. If you're not using Git yet, run `git init` and make one commit first.
- **Node.js 22.20 or later**: only needed if you install with `npx skills` (covered in the next step).

</Callout>
