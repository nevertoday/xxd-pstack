## What this step does

You tell pstack which models to use and how much to spend. It takes one command, then you answer a few questions:

<Copy id="setup" title="With the Claude Code plugin, type /pstack:setup-pstack" code="/setup-pstack" />

`/setup-pstack` checks which models you can use, asks about your budget, shows you what it plans to use for each <Term k="模型角色" />, then writes a small config file. From then on, every skill reads it when handing out work.

## First question: reasoning budget

The <Term k="推理预算" /> is how long the model gets to "think." You get four options:

| Option | What it means | Good for |
| --- | --- | --- |
| `large` | xhigh level, same as the default | Pick this if you're not sure |
| `unlimited` | max level; models that can't reach max stop at their highest (grok stops at xhigh, for example) | Very hard, high-stakes work where cost doesn't matter |
| `medium` | high level | Saving a bit |
| `small` | medium level | Mostly simple tasks, tight budget |

## Second question: which model for each role

pstack splits the work into a few roles, and each one can use a different model:

- **Coding roles** (features, refactors, bug fixes, performance...): grok by default. Fast and cheap.
- **Judgment roles** (the hardest changes, writing, making calls): opus 5.5 by default.
- **Review panel**: opus 5.5 plus grok by default, **two model families on purpose, so they poke holes in each other's work**. It sends out one subagent per model on the panel.
- **Swarm workers**: the model each `/swarm` worker uses by default.

Only change the roles you care about. Any role you leave out uses the default. A role set to `auto` or `inherit-parent` means "don't pick a separate model, use the same one as the main conversation."

<Callout type="tip" title="If you use Claude Code">
Claude Code subagents can only use Claude models (opus, sonnet, haiku, and so on). Roles that default to grok will just use your current session's model in Claude Code. `/setup-pstack` asks based on the models you actually have, so just follow along.
</Callout>

## Two last offers: a verification skill

After the models are set, it checks whether your project has a way to "prove the app really works." If not, it **offers once** to generate a <Term k="验证技能" /> for you.

<strong>As a beginner, say yes.</strong> The author calls it the single highest-payoff piece of the whole pack: an AI that can check its own work keeps going until the check passes. One that can't has to hand every result back to you to check by hand. Once it's generated, it runs it end to end itself, and only hands it over once it works.

Next it may offer to generate a <Term k="形式化验证" /> skill. If your code has concurrency, retries, state machines, parsers, or other spots where "a bug is expensive and tests rarely hit it," say yes. Otherwise say no for now. You can add it any time.

## When you're done, start a new conversation

The config is written here:

| Tool | File |
| --- | --- |
| Cursor | `~/.cursor/rules/pstack-models.mdc` |
| Claude Code | `~/.claude/rules/pstack-models.md` |
| Codex and other tools | `~/.agents/pstack-models.md` |

Cursor and Claude Code only read it **when a new conversation starts**, so <mark>once you're set up, close this conversation and start a new one</mark>.

## Stuck?

<Q q="What if I want to change models or budget later?">
<p>Run <code>/setup-pstack</code> again. Roles you've changed are kept. To reset a role to its default, delete that line from the config file.</p>
</Q>
<Q q="pstack updated its default models, but mine didn't change.">
<p>Your old config still has the old defaults written into it. Delete those lines (or the whole file), then run <code>/setup-pstack</code> again.</p>
</Q>
<Q q="I said no to the verification skill, and now I want it.">
<p>Run <code>/create-verification-skill</code> any time. See <a href="/en/guide/6-verify-ship/">Step 6</a> for details.</p>
</Q>
