## First, make sure you can trust it

Before you let go, all four of these should hold:

1. **You know what good looks like**: you did it once, or watched it done once.
2. **It has the tools you'd use**: a verification skill, logs.
3. **Every step can prove itself**: it stops when it falls short.
4. **Repeated mistakes now have checks**: you've read a few transcripts.

<mark>Until all four hold, run it while you're watching.</mark>

## Write bedtime instructions

<Copy id="contract" title="Bedtime instructions" code={`/poteto-mode I'm going to bed. In a fresh worktree off main, migrate every caller to the new parser.
Done means: no old callers left, every parser fixture passes, and the old API is deleted.
Keep a decision log. You don't need to ask me before committing.
/loop until done. If you've been stuck for hours and truly can't go on, stop and write down why.`} />

What each sentence does:

- **I'm going to bed**: keep going, don't ask me.
- **Done means**: it checks this every round.
- **A fresh <Term k="worktree" />**: a separate working folder, away from your own work.
- **Don't need to ask before committing**: it won't sit waiting for your OK.
- **/loop until done**: it keeps checking whether it's done (built into Cursor and Claude Code).
- **If stuck, stop and write why**: stopping beats eight hours of busywork.

<Callout type="no" title={`"Work for 4 hours" isn't a done condition`}>
A duration can't be checked. Give it a condition that clearly passes or fails.
</Callout>

## In the morning: read "needs attention" first

<Copy id="audit" code="/show-me-your-work Walk me through what you did last night" />

**What you get**: a summary. Before handing it back, a model from another family reads the log and adds a "needs attention" section. <strong>Read that section first, then the lines it points to.</strong>

The log is `decisions.tsv` (or `.audit/<task-name>.tsv` when several tasks share a folder). By default it stays on your machine.

Just want progress? Type `/ketchup` in that chat. It tells you what changed and what's waiting on your call.

## Stuck?

<Q q="I'm not comfortable letting it commit on its own.">
<p>Leave out "you don't need to ask me before committing", or use Autopilot-stack so it stops once things are verified.</p>
</Q>
<Q q="I woke up and it had been going in circles.">
<p>Most likely the done condition wasn't firm enough. Use <code>/reflect</code> to record the lesson, and <code>/correct</code> to turn repeated mistakes into checks.</p>
</Q>
<Q q="I want to stop it partway.">
<p>Tell it "pause" or "I'm going offline". It wraps up the current step and writes a resume note. A new chat can pick up from there.</p>
</Q>
