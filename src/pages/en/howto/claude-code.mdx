## Install it

In the Claude Code chat box, type these two lines one after the other:

<Copy id="cc-plugin" title="Install from the plugin marketplace" code={`/plugin marketplace add cursor/plugins
/plugin install pstack@cursor-plugins`} />

This installs the full set, so `/poteto-mode` has everything it needs. If you're not sure, use this.

**To pick skills yourself**, type this in your terminal (not the chat box):

<Cmd c="npx skills add backnotprop/pstack" />

Check the skills you want and choose Claude Code as the tool. The skills go into `.claude/skills/`. For what to pick, see [Install only a few skills](/en/howto/pick-skills/).

## Add pstack: before commands

If you installed from the marketplace, commands start with the plugin name. Where this tutorial says `/poteto-mode`, you type:

<Cmd c="/pstack:poteto-mode" />

The same goes for other commands, like `/pstack:how`. Other pages on this site leave the prefix out, so add it yourself. If you used `npx skills`, no prefix is needed.

<Callout type="warn" title="Skills don't start on their own">
Except for `setup-pstack`, every skill runs only when you type it yourself. Saying "help me fix a bug" won't switch on `/pstack:poteto-mode`.
</Callout>

## Pick models, then start a new session

After installing, run this once:

<Cmd c="/pstack:setup-pstack" />

It asks about your <Term k="推理预算" /> (how long models think), then assigns a model to each <Term k="模型角色" />. Finally it writes one file: `~/.claude/rules/pstack-models.md`.

Claude Code reads the `.md` files in that folder each time a new session starts. So <mark>after setup, quit and open a new session before you start working</mark>. The current session still has the old settings.

A model is written as "name + level," like `opus xhigh`. The only names are `opus`, `sonnet`, `haiku`, and `fable`. Keep these lines in this one file. Don't copy them into `CLAUDE.md`.

## How to set it up well

**Most people should pick Balanced**: the session runs on opus, and sonnet writes the code.

Why? Two things decide which models get used:

- **The session model**: the one you pick with `/model`, the AI you talk to directly. It picks the approach, hands out work, and reviews every change.
- **Each line in the settings file**: which model each helper AI (<Term k="子代理" text="subagent" />) runs on.

By default, pstack has grok write the code. Claude Code can't use grok, so those lines become `inherit-parent`. That means "follow the session model."

So if you change nothing and run the session on opus, opus does all the work. It costs the most, and both review seats are the same model. Balanced moves the coding to sonnet. That halves the price and puts two different models on reviews.

Prices are API list prices as of October 2026, per million <Term k="token" text="tokens" />. On a subscription, pricier models use up your limits faster:

| Model | Input / output | Good for |
| --- | --- | --- |
| fable | $10 / $50 | Strongest, when cost is no object |
| opus | $4 / $20 | Session, judgment, hardest changes |
| sonnet | $2 / $10 | Writing code, second review seat |
| haiku | $0.1 / $0.5 | Not recommended |

Why not haiku: checking the results uses the same model as the coding line. Make that the cheapest model, and the checks get weaker too.

### How to write it in

1. Pick the session model with `/model`.
2. Run `/pstack:setup-pstack` and pick the budget for your plan.
3. When it asks whether to change any roles, paste it the file above and have it write that.
4. Quit and start a new session.

## You see "Skipped in Claude Code"

Cursor's scheduled tasks, its Bugbot review bot, and its cloud agents don't exist in Claude Code. Steps that use them get skipped. The reply gets one line, and it moves on:

<Copy id="cc-skip" title="You'll see a line like this" code="Skipped in Claude Code: <which step>. <why it was skipped>." />

Opening a <Term k="PR" /> still works, using `gh pr create` instead. `/loop` exists here too. If it says it left a placeholder (like a missing link), check what's missing and fill it in if needed.

## Turn on auto-update

Claude Code doesn't update third-party plugins by default. To turn on auto-update:

1. Type `/plugin` in the chat box.
2. Open the **marketplaces** tab.
3. Select `cursor-plugins`.
4. Choose **enable auto-update**.

To update by hand, run:

<Cmd c="claude plugin update pstack@cursor-plugins" />

If an update changes the default models, your old settings file keeps the old ones. For the fix, see [Update, check, uninstall](/en/howto/update-remove/).

## Stuck?

<Q q="I typed /poteto-mode and nothing happened. It's not in the menu either.">
If you installed from the marketplace, type `/pstack:poteto-mode`. Type `/pstack:` first, and the menu lists only pstack's commands.
</Q>
<Q q="I ran setup, but the models I chose didn't take effect.">
The settings file is only read when a new session starts. Quit and open a new one. If that doesn't help, open `~/.claude/rules/pstack-models.md` and check the line shows the model you chose.
</Q>
<Q q="A reply says /arena skipped its judge, or found no reviewer from another family.">
A few steps want a model from "another family" to review, like the `/arena` judge. All Claude models count as one family. So it skips the judge, picks itself, and says so. The `arena cross-judge pool` line does almost nothing here. For another vendor's eyes, take the review that matters to Codex or Cursor and run `/interrogate` there.
</Q>
<Q q="The skills use Cursor's names. Do I translate them?">
No. The plugin includes a mapping guide (`docs/harness/claude-code.md`), and the AI translates on its own. For example, `.cursor/rules/` becomes `CLAUDE.md` (or `AGENTS.md` if there isn't one), and cloud agents become a local <Term k="worktree" />.
</Q>
<Q q="The AI says the Skill tool can't call pstack's skills. Is it broken?">
No. In Claude Code, most pstack skills can't be called that way. The AI reads that skill's `SKILL.md` directly and follows it. Keep typing commands as usual.
</Q>
<Q q="I let it run overnight and found it stuck on a permission prompt.">
Before you let it run alone, allow the common commands: git, gh, your test and build commands. Claude Code's built-in `/fewer-permission-prompts` finds the look-only commands you use often and writes them into the project's `.claude/settings.json`. Whether to allow commands that change things is your call.
</Q>
