## One command to install

Each pstack skill is a `SKILL.md` in the common <Term k="Agent Skill" /> format, so it installs without Cursor. In your terminal, type:

<Cmd c="npx skills add backnotprop/pstack" />

It needs Node.js 22.20 or newer. If you're not sure, run `node -v` first.

Check the skills you want, then pick which tools to install into. If you don't know which to check, select all. For just a few, see [Install only a few skills](/en/howto/pick-skills/).

<Callout type="tip" title="Install for every project">
<p>By default it installs only into the current project folder. To make it available in every project, add <code>-g</code>:</p>
<p><Cmd c="npx skills add backnotprop/pstack -g" /></p>
</Callout>

## Check where it installed

Look in the matching folder for subfolders like `poteto-mode`:

| Tool | This project | All projects (-g) |
| --- | --- | --- |
| Codex and others | `.agents/skills/` | `~/.agents/skills/` |
| Claude Code | `.claude/skills/` | `~/.claude/skills/` |
| Pi | `.pi/skills/` | `~/.pi/agent/skills/` |
| Cursor | `.cursor/skills/` | `~/.cursor/skills/` |

Codex also reads `~/.codex/skills/`.

<mark>Skills don't start on their own</mark>. Except for `setup-pstack`, each one runs only when you name it.

## Pick models

After installing, run `setup-pstack` once. It lists the models you can use, asks about your <Term k="推理预算" /> (how long models think), then writes one file:

<Copy id="codex-file" title="Where the settings file lives" code="~/.agents/pstack-models.md" />

The skills read it themselves when they pick a model, so you don't need a new conversation.

<Callout type="warn" title="Run setup at least once">
pstack's default model names are written for Cursor. If your tool lacks a name, the skill switches to the closest one. If there's nothing close, it uses your current conversation's model and says so. Run setup once, and every role gets a model you actually have.
</Callout>

## Your first task

In Codex, you name a skill with `$` plus its name, like `$poteto-mode`. Commands on this site are written for Claude Code by default (`/pstack:poteto-mode`). Pick Codex here, and every command on the site switches to the `$` form:

<ToolPick />

Send your first task like this:

<Copy id="codex-first" title="In Codex, name a skill with $" code="$poteto-mode add a --json flag to this command. The existing text output must stay byte-for-byte identical. Verify both outputs." />

You can also say "use the poteto-mode skill for this." In other tools, use their syntax instead. For how to write this message well, see [Your first task](/en/guide/3-first-task/).

## What your tool lacks, it works around

The skills use Cursor's names, and the AI translates them. A few things you'll notice:

- **No way to send out helpers** (<Term k="子代理" text="subagents" />): steps meant to run side by side run one at a time, a bit slower.
- **No question tool**: it lists numbered options in the chat.
- **No `/loop`**: it uses a timed wait command and checks again later.
- **No Custom Mode**: only Cursor has it. Write `poteto-mode` at the start of each new task.

`deslop`, `control-cli`, and `control-ui` come from another Cursor plugin. Without them, the AI uses the tools you have, like Playwright or tmux.

## Stuck?

<Q q="npx skills errors out and won't run.">
Run `node -v` first. If it's below 22.20, upgrade Node.js and try again.
</Q>
<Q q="I can't find pstack's skills in another project.">
<u>By default it only installs into the project you were in</u>. Run it again in the new project, or add `-g` to install for every project.
</Q>
<Q q="I changed the model settings, but it doesn't seem to apply.">
Open `~/.agents/pstack-models.md` and check the line shows the model you chose. Then check that name exists in your tool. If it doesn't, the skill switches to the closest one and says so in the reply.
</Q>
