## The short answer

- Planning to use `/poteto-mode`? <mark><strong>Install everything</strong></mark>. It uses every principle skill and most of the other skills, so picking a few just leaves things missing.
- Only want one or two features, like removing AI flavor or understanding code? Pick from the tables below, and remember to bring along anything marked "also install."

If you installed with Cursor's `/add-plugin pstack` or the Claude Code plugin marketplace, you already have the full set and can skip this page. Only `npx skills` lets you pick.

## 17 skills that work on their own

These skills don't call any other pstack skill. Install one and it works:

| Skill | In one line |
| --- | --- |
| `unslop` | Takes the AI flavor out of text |
| `bro` | Says the last reply again in plain words |
| `how` | Explains how a piece of code works right now |
| `tdd` | Writes a failing test first, then fixes |
| `typescript-best-practices` | Keeps you to the type rules when writing TypeScript |
| `arena` | Has several AIs each solve the same problem, picks the best, and grafts in the rest |
| `swarm` | Splits the work into pieces, runs them in parallel, and sums up in one report |
| `interrogate` | Has several models attack your change and keeps only the problems that produce a real failure |
| `reflect` | When a task is done, turns what was learned into suggested skill changes |
| `show-me-your-work` | Writes one line in a decision log for every decision |
| `figure-it-out` | Designs a rigorous approach on the spot when no playbook fits |
| `automate-me` | Builds a mode skill of your own from your chat history |
| `correct` | Blocks a kind of mistake at the root when it keeps coming back |
| `benchmark-checklist` | Checks a measured performance number before you publish it |
| `in-your-own-words` | Has the AI restate your goal and problem first |
| `sharpen` | Makes your prompt deeper, not longer |
| `statechart` | Draws "what the user will see" as a checked state diagram |

## These need others installed with them

The skills below call other skills. Install the left column without the right, and when it reaches that step it won't find what it needs:

| To install | Also install |
| --- | --- |
| `teach` | `how`, `why` |
| `why` | `how` |
| `technical-writing` | `unslop` |
| `architect` | `arena`, `how` |
| `blast-radius` | `arena`, `how`, `why`, `unslop` |
| `create-verification-skill` | `maintain-verification-skill` |
| `create-formal-verification-skill` | `maintain-formal-verification-skill`, `statechart` |
| `ketchup` | `bro` |
| `ketchup-video` | `ketchup`, `bro` |
| `poteto-mode` | Every `principle-*` principle skill, plus most of the other skills |
| `poteto-help` | Whichever skills you want to ask about |

<Callout type="tip" title="A few not listed in the tables">
The README's two tables leave out `recall`, `no-comments`, `setup-pstack`, and `make-bot-ui`. Their descriptions show that `recall` uses `why` and `unslop`, and `no-comments` mentions `how`, `why`, and `architect`. To be safe, bring the mentioned ones along when you install those two. `setup-pstack` doesn't depend on other skills, but install it if you want to choose models yourself. Without it, each skill uses its own default model.
</Callout>

One more detail: skills that send out <Term k="子代理" text="subagents" /> (like `arena` and `swarm`) rely on a section in `poteto-mode` to decide how long each subagent should think. Without `poteto-mode` they still run, but always at the default reasoning effort.

## Common combinations

| You want | Check these |
| --- | --- |
| Just understanding code | `how`, `why`, `teach` |
| Just removing AI flavor from text | `unslop`, `bro` |
| Writing docs, a README, or PR descriptions | `technical-writing`, `unslop` |
| Settling the design before changing code | `architect`, `arena`, `how` |
| Several models picking at it before you commit | `interrogate` |
| Writing a test first when fixing a bug | `tdd` |
| Letting the AI verify your app itself | `create-verification-skill`, `maintain-verification-skill` |
| The full pstack experience | Select all |

The last row is serious. The most valuable part of pstack is `/poteto-mode` chaining these skills together by playbook. Each skill is useful alone, but chained together is how the author, poteto, really uses them day to day.

## How to pick from the npx skills list

Run this in your terminal:

<Cmd c="npx skills add backnotprop/pstack" />

It lists every skill, and you can search the list. Type a skill name to filter it, and select everything you want, including the "also install" column above. After the skills, choose which tools to install them into (Codex, Claude Code, and so on).

If you realize you missed something, run the same command again and add what's missing. For install details per tool, see [Use it in Codex and other tools](/en/howto/codex/).

## Stuck?

<Q q="I only installed teach, and it's missing things when it runs.">
`teach` needs `how` and `why` to do its job. Run `npx skills add backnotprop/pstack` again and check those two as well.
</Q>
<Q q="I only installed a few skills. Can I still use /poteto-mode?">
Not recommended. `poteto-mode` reads every principle skill and calls most of the other skills along the way. Whatever is missing, that step won't be done fully. If you want it, install everything.
</Q>
<Q q="Do I need to pick the principle skills (principle-*) separately?">
Only when you install `poteto-mode`, and then you need all of them. You won't type them directly. They're there for `poteto-mode` to read. You only need to say their names when steering, see <a href="/en/howto/steer/">Pull it back in one line</a>.
</Q>
