## Commands by install route

Pick the tab for the command you typed back then:

- `npx skills add` → skills command line
- `/plugin install` → Claude Code plugin
- `/add-plugin` → Cursor plugin

Can't remember? If commands need the `pstack:` prefix, it's the Claude Code plugin.

<Tabs id="ur" items={[["skills","skills command line"],["cc","Claude Code plugin"],["cursor","Cursor plugin"]]}>
<div slot="skills">
<p>Run these in your terminal (not in the AI chat box):</p>
<p><Cmd c="npx skills list" /> See which skills are installed.</p>
<p><Cmd c="npx skills check" /> Check for new versions.</p>
<p><Cmd c="npx skills update" /> Update to the latest.</p>
<p><Cmd c="npx skills remove" /> Uninstall skills.</p>
<p>Skills installed without <code>-g</code> live only in the project you were in at the time.</p>
</div>
<div slot="cc">
<p>Third-party plugins don't auto-update by default. To update once by hand (run it in your terminal):</p>
<p><Cmd c="claude plugin update pstack@cursor-plugins" /></p>
<p>To update automatically: type <code>/plugin</code>, open the <strong>marketplaces</strong> tab, select <code>cursor-plugins</code>, then choose <strong>enable auto-update</strong>.</p>
<p>Type these in the Claude Code chat box:</p>
<p><Cmd c="/plugin list" /> See which plugins are installed and whether they're on.</p>
<p><Cmd c="/plugin uninstall pstack@cursor-plugins" /> Uninstall.</p>
<p><Cmd c="/plugin disable pstack@cursor-plugins" /> Pause it. Turn it back on later with <code>/plugin enable pstack@cursor-plugins</code>.</p>
<p>After uninstalling or pausing, type <code>/reload-plugins</code> or restart Claude Code. To also remove the plugin store you added at install: <code>/plugin marketplace remove cursor-plugins</code>. Note that this also uninstalls every other plugin you installed from that store.</p>
</div>

<p>Manage it from Customize in the sidebar. pstack doesn't document update steps for the Cursor plugin, so follow Cursor's own interface.</p>
</div>
</Tabs>

## After updating: clear the old defaults

`/setup-pstack` writes each <Term k="模型角色" />'s model into the settings file, one line each. If a new version changes the default models, your file still names the old ones. <mark>When a skill reads that line, it keeps using the old model</mark>.

Pick one:

1. Open the settings file and delete the lines you never changed on purpose. Those roles then use the new defaults.
2. Delete the whole file and run `/setup-pstack` again.

| Tool | Settings file |
| --- | --- |
| Cursor | `~/.cursor/rules/pstack-models.mdc` |
| Claude Code | `~/.claude/rules/pstack-models.md` |
| Codex and others | `~/.agents/pstack-models.md` |

<Callout type="ok" title="Rerunning is safe">
When you rerun `/setup-pstack`, roles you changed on purpose are kept. Start a new conversation afterward, or it won't apply.
</Callout>

## After uninstalling: delete the settings file too

Uninstalling doesn't delete the settings file. Claude Code reads it into every new session, so it just takes up space. If you're done with pstack, delete that file from the table above as well.

A <Term k="验证技能" /> it generated (a folder like `verify-your-app`) belongs to your project and isn't removed with pstack.

## Stuck?

<Q q="I updated, but it still uses the old models.">
Most likely the old settings file. Delete that role's line, or rerun `/setup-pstack`, then start a new conversation.
</Q>
<Q q="I can't see pstack's skills in npx skills list.">
Make sure you're running it in the project folder where you installed. Skills installed in a project and skills installed with `-g` live in different places.
</Q>
