## First, remember how you installed it

How you update and uninstall depends on which route you took:

| What you typed back then | Route |
| --- | --- |
| `npx skills add backnotprop/pstack` | skills command line |
| `/plugin install pstack@cursor-plugins` | Claude Code plugin |
| `/add-plugin pstack` | Cursor plugin |

Can't remember? If you used the skills command line, the skills show up in folders like `.claude/skills/` or `.agents/skills/`, one subfolder per skill. If you used the Claude Code plugin, commands need the `pstack:` prefix, like `/pstack:poteto-mode`.

## After updating: old settings still pin old defaults

This is the easiest trap to fall into when updating.

The settings file `/setup-pstack` writes hard-codes the model for each <Term k="模型角色" />, one line each. If a new version of pstack changes the default models, your old file still says **the old defaults**. <mark>The skill reads that line and keeps using the old model, so the new defaults never reach you</mark>.

Two ways to fix it, pick one:

1. Open the settings file and delete the role lines you never deliberately changed, the ones that were just written in from the defaults. Deleted roles go back to the skill's new defaults.
2. Delete the whole file and run `/setup-pstack` again.

Where the settings file is depends on your tool:

| Tool | Settings file |
| --- | --- |
| Cursor | `~/.cursor/rules/pstack-models.mdc` |
| Claude Code | `~/.claude/rules/pstack-models.md` |
| Codex and other tools | `~/.agents/pstack-models.md` |

<Callout type="ok" title="Rerunning won't wipe what you changed">
When you rerun `/setup-pstack`, roles whose model differs from the default (the ones you changed on purpose) are kept. So rerun it without worry. Rerunning also removes role lines that are no longer used, and tells you which ones it removed.
</Callout>

After the change, you again need to start a new conversation (in Cursor and Claude Code) for it to take effect.

## After uninstalling: the settings file is still there

Uninstalling the skills or the plugin doesn't delete your model settings file. Be especially careful in Claude Code: it reads every `.md` file in `~/.claude/rules/` into every new session. If you uninstall pstack but keep `pstack-models.md`, those role lines still show up in every session, taking up space for nothing.

If you're done with pstack for good, delete the matching file from the table above too.

Also, if you had `/setup-pstack` generate a <Term k="验证技能" /> (a folder in your project like `verify-your-app`), it belongs to your project and isn't removed along with pstack. Keep it if you still want it, or delete it yourself if you don't.

## Stuck?

<Q q="I updated, but it still runs the old models.">
Most likely it's the old settings file described above. Open it and look at that role's line, then delete it or rerun `/setup-pstack`. Then start a new conversation.
</Q>
<Q q="pstack in Claude Code never updates.">
Third-party plugin marketplaces don't auto-update by default. Run `claude plugin update pstack@cursor-plugins` by hand, or turn on auto-update for `cursor-plugins` in the marketplaces tab of `/plugin`.
</Q>
<Q q="npx skills list doesn't show pstack's skills.">
Make sure you're running it in the project folder where you originally installed. Skills installed into your user folder with `-g` and skills installed in a project live in two different places.
</Q>
