## 这一步做什么

用 <Term k="poteto-mode" /> 做一件真实的小事。挑一个你自己项目里**真实但不大**的需求，像跟同事交代工作一样说出来。

作者给新手的建议只有一句：<mark><strong>给它一个目标，再给它一个检查的办法，用你自己的话说。</strong></mark> 你不用点名剧本，也不用列技能。

## 先看一个例子

假设你有一个命令行工具，想加一个 `--json` 参数：

<Copy id="first" title="官方指南里的第一个任务" code="/poteto-mode 给这个命令加一个 --json 参数。原来的文本输出一个字节都不能变。两种输出都要验证。" />

换成你的项目，比如一个 Chrome 插件的设置页：

<Copy id="first-ext" title="换成你的项目" code="/poteto-mode 在设置页加一个「导出设置」按钮，把当前设置下载成一个 JSON 文件。已有的设置项和保存逻辑不能变。验证：导出的文件能被 JSON 解析，里面的值和 chrome.storage 里存的一模一样，给我看两边的实际内容。" />

## 一句好提示词里有什么

最多五样东西，每样一句话就够：

| 写什么 | 为什么 | 例子 |
| --- | --- | --- |
| **目标** | 说清楚哪里不对、或者你想要什么 | 加一个导出按钮 |
| **怎么算做完** | 必须能判断「过」还是「不过」 | 导出的文件能被解析，值和存储里一样 |
| **想看什么证据** | 要一个你能自己检查的东西 | 两边的实际内容 / 截图 / 前后数字 |
| **你已经知道的** | 省它一轮搜索 | 一行报错、一个复现步骤、一个链接 |
| **真正的约束** | 会改变它的做法 | 先复现 / 先别改代码 / 行为不能变 / 做之前让我看看 |

有两样东西**最好别写**：

- **具体怎么做。** 说要达到什么，给它留出找到更好办法的空间。
- **你猜的原因（至少一开始别说）。** 你一说，它就只在你指的地方找。等它自己复述完问题，再补你的猜测。

<Callout type="no" title="「做好一点」「花一个小时弄弄」不是检查">
它没法判断这算过还是不过，最后只能凭感觉交差。换成一条能跑的命令、一个能看的结果。
</Callout>

## 发出去以后看什么

**第一条回复**：它会用自己的话说出你的目标、你在解决什么问题、它预计最小的改动是什么。它不会等你确认就往下做；理解错了，马上打断它。

**<Term k="待办清单" />**：前几项是它匹配到的<Term k="剧本" />的步骤，原样抄进来。上面的例子会匹配到「功能」剧本：先用 `/how` 读懂相关代码，再用 `/architect` 定设计，然后派子代理写代码、在真实界面上验证，最后整理成小提交、开 <Term k="PR" />。决定不做的步骤不会消失，后面会写着 `skip: 理由`。

**最后的回复**：应该带着你要的证据，比如真实的命令和输出。验证不了的，好的回复会写「说不准」。<strong>很自信、但没有证据的回复，是危险信号。</strong>

## 接着聊：越短越好

对话里已经有上下文时，后续消息可以非常短：

<Copy id="short" title="这些都够用" code={`/poteto-mode 做吧
继续
一直做到完成为止`} />

能这么短，是因为剧本记着结构，你的话只需要带着意图。

**换任务时说一声「new task」**，否则它会把你的新问题当成上一个任务的下一步：

<Copy id="newtask" code="/poteto-mode new task. 查一下为什么退出登录后缓存还在。先别改代码。" />

「先别改代码」会把这个任务钉在只读的「调查」剧本上。

<Callout type="tip" title="用 Cursor 的话">
从 `/` 菜单选 `/poteto-mode` 后按 Option+Enter（Mac）或 Alt+Enter（Windows），它会变成 <Term k="Custom Mode" />，每一轮都在，不用每句都打。普通 Enter 只管这一条消息。
</Callout>

## 别在提示词里排技能

「先用 /how，再用 /architect，再用 /arena……」这种写法，是官方指南点名的头号坑：剧本已经排好了顺序，你手写的顺序往往会打乱它、或者漏掉它本来要做的步骤。只有想改掉某个默认选择时才点名一个技能。

## 卡住了？

<Q q="它理解错了我的意思。">
<p>直接说：「不对，我的目标是……」。理解错了出现在第一条复述里最便宜，只花你一条消息。对于很乱的需求（一长串讨论、一个说不清的 bug），可以让它先只复述：<code>/poteto-mode 读一下这个讨论，用大白话复述根本问题。先别改代码。</code></p>
</Q>
<Q q="它跳过了我觉得重要的步骤。">
<p>看清单里那一项后面的 <code>skip:</code> 理由。不同意就说：「第 2 步不要跳，先复现。」</p>
</Q>
<Q q="回复太长太专业，看不懂。">
<p>打 <code>/bro</code>，它会把上一条用大白话重说一遍。</p>
</Q>
