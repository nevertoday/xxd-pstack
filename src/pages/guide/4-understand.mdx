## 为什么先看懂

<mark>改自己没看懂的代码，是隐蔽 bug 上线的头号原因。</mark>AI 也一样。

AI 失手通常只有两种原因：**理解错了你要什么**，或者**没有把活干对所需要的上下文**。第 3 步的提示词写法解决第一种，这一步解决第二种。

pstack 给了四个入口。它们还有一个附带的好处：都要求 AI 用你能检查的话把自己的理解讲出来。这是你监督一个「可能比你更懂这段代码」的 AI 的办法。

| 技能 | 回答的问题 |
| --- | --- |
| `/how` | 这段代码**现在**是怎么工作的？ |
| `/why` | 它**当初为什么**写成这样？理由还成立吗？ |
| `/teach` | 把上面两个合起来，讲到我**真的懂** |
| `/recall` | 这件事**我自己**之前做到哪了？ |

## 原因不明？先要调查结果，别要修复

<Copy id="inv" code="/poteto-mode 查一下为什么后台任务每隔几小时会超时。告诉我已知的事实、你用了哪些数据、你最有把握的几个猜测。先别改代码。" />

「先别改代码」会把它送进只读的「调查」<Term k="剧本" />：跑 `/how`，涉及「为什么」的问题再加 `/why`，最后给你一份带出处的解释；要在几个方案里选时，给你一个推荐加一张利弊表。

「你用了哪些数据」这半句很值：它会把**证据**和**猜测**分开写。调查结果指向一个修复时，开一个新任务去修（说「new task」）。

## /how：现在是怎么工作的

问你真正想问的：

<Copy id="how" code="/how 通知是怎么去重的？查订阅者的时候有没有 N+1 查询？" />

它会读代码，像资深同事带你熟悉一个模块那样回答：运行时的流程、关键的数据类型、不显眼的地方。模块很大时，它会先派两到四个只读的<Term k="子代理" />分头读；问题很窄时就直接读、直接讲。

## /why：当初为什么这么写

<Copy id="why" code="/why 重试上限为什么是 5？这个理由现在还成立吗？" />

它先翻 Git 历史，再去查你接入的其他来源（issue、文档、团队聊天、监控、错误追踪等，看你装了哪些 MCP），并行地查。报告里每条都有出处，分清直接证据和推测，记录不足时会说「看起来是」。查不到也会如实报告，因为「当时没人写下原因」本身就是一个答案。

两个可以连着用：怀疑历史能解释眼前的乱象时，说「先 why 再 how」。

## /teach：讲到你真的懂

<Copy id="teach" code="/teach 讲讲这个 PR 是怎么改重试的。说服我它修的是根因，不是表象。" />

光看摘要不够的时候用它。它跑 `/how` 和 `/why`（小改动可能只跑一个），把结果编成一篇大白话的讲解，一张图一张图往上搭。

「说服我」这个说法值得常用：它把一次导览变成了一个你可以质疑的论证。也可以拿来问 AI 自己的选择：

<Copy id="teach2" code="/teach 讲讲你为什么这么实现、而不是用队列。你放弃了什么，为什么？" />

要它讲，它就得真去读代码、给每个说法找证据，而不是自信地说完就走。

## /recall：找回你自己的上下文

<Copy id="recall" code="/recall 帮我回忆上周导出功能那块做到哪了" />

它翻你最近的对话记录，加上共享的记录（issue、以前的修复、还在报的错误），交给你一份「现在到哪了、下一步是什么」的简报。在一个老话题上开始新工作时，先让它把上下文加载进来，再给新材料：

<Copy id="recall2" code="/recall 我昨天在虚拟列表上的工作，然后读一下这个 bug 报告。" />

## 接手别人（或者上周的你）没做完的活

<Copy id="pickup" code="/poteto-mode 接手这个分支。读一下决策日志，弄清楚哪些做完了，从那里接着做。别重做已经完成的部分。" />

「接手」剧本会把之前留下的记录当成依据：还原分支状态和做过的决定，说出从哪里接着做，并且对照原始目标去核实前人说「做完了」的那些部分。

<Callout type="warn" title="别因为「它反正会读代码」就跳过这一步">
不先建立对代码的理解就动手的 AI，往往会在第一个看起来合理的地方修掉症状。先跑一次 `/how`，比多出一个 bug 便宜。
</Callout>

## 卡住了？

<Q q="/why 说查不到原因。">
<p>正常。它只能查到你接入的来源。想让它查 issue、聊天记录、文档，需要先在你的工具里接上对应的 MCP（比如 GitHub、Linear、Slack、Notion）。没有的话，它至少会翻 Git 历史。</p>
</Q>
<Q q="讲得太专业了。">
<p>说「讲给第一次接触这个项目的人听」，或者讲完打 <code>/bro</code>。</p>
</Q>
