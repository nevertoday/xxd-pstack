## 这一步为什么放在后面

前面所有步骤的回报都在这里：一个你信得过、能自己验证的 AI，才是你能放心留下来独自做难活的 AI。让这件事安全的不是运气，而是三样东西：**一个能检查的完成条件、一个隔离的工作目录、一份你早上能审的<Term k="决策日志" />。**

## 先赢得信任，再让它循环

一个你不信任的循环，只会更快地产出没检查过的活，而且越滚越乱。放它自己跑之前，这四条都要成立：

1. 你自己做过一次，或者看着 AI 做过一次，知道「好」长什么样。
2. 它有你自己会用的工具和信号：验证技能、profiler、日志。
3. 每个阶段都能证明自己的成果，不达标时能叫停。
4. 你读过几次对话记录，把反复出现的失败变成了工具、技能或检查。

<mark>四条都满足之前，就在你看着的时候跑。</mark>

## 睡前合同

一份好的交接有：目标、完成条件、权限、一个逃生口。不用很长：

<Copy id="contract" title="睡前合同" code={`/poteto-mode 我要去睡了。在一个从 main 新开的 worktree 里，把所有调用方迁到新的解析器。
完成的标准：旧的调用方一个都不剩，所有解析器测试数据都通过，旧接口已删除。
记决策日志。提交之前不用问我。
/loop 直到完成。如果卡了几个小时真的走不下去，就停下来写清楚为什么。`} />

每一句都在买东西：

| 这句话 | 买到了什么 |
| --- | --- |
| 我要去睡了 | 告诉它这次别再问我，一直往下做 |
| 完成的标准是…… | 把目标变成每一轮都能跑的检查 |
| 从 main 新开一个 worktree | 不和你开着的其他东西撞车 |
| 提交之前不用问我 | 提前回答它本来会卡住等你的那个权限问题 |
| `/loop` 直到完成 | 让它按事件或定时反复检查完成条件（Cursor 和 Claude Code 自带，不是 pstack 的技能） |
| 卡住了就停下来写清楚 | 真走到死胡同时，停下来写原因，好过花八小时「创造性地重新理解目标」 |

因为你要回来再审，`/poteto-mode` 会把这件事交给 `/figure-it-out`：先设计好运行的几个阶段，再接上决策日志。

## 它一晚上在干什么

每一轮都是同样的四件事：

1. 检查完成条件。
2. 做一个最小的、有理由的改动。
3. 对照真实产物验证。
4. 有进展就提交，没进展就丢掉；不管哪种，都在日志里记一行。

一次改动、一次检查、一行日志。没帮上忙的改动会被丢掉，不会留着混过去。卡在平台期意味着换方向，不是停下；完成条件也**绝不会悄悄放宽**来宣布胜利。

想有意停下来，跟它说「暂停」，或者说你要下线、要重启工具了。「安全暂停」剧本会做完或退回当前这一步，提交一个进行中的检查点，写一份续接说明；新对话可以从那份说明接着做。说「继续」永远不会触发暂停。

## 第二天早上：审决定，不重读整夜

<Copy id="audit" code="/show-me-your-work 把你昨晚做的事给我讲一遍" />

日志每一行记着时间、阶段、决定、理由、证据在哪、结果，存在 `decisions.tsv`（几个任务共用目录时在 `.audit/<任务名>.tsv`）。默认只在本地；活够重要、审的人需要这条记录才放心时，再提交进仓库。

交回总结之前，它会派**另一个模型家族**的审阅者读日志和对话，回复最后有一个「需要注意」的部分。<strong>先读这一部分，再去看它指向的那几行。</strong> 你审的是决定，不是一整夜。

只想知道进展、不想审：在跑这个任务的对话里打 `/ketchup`。它只读，用大白话告诉你自上条消息以来变了什么，并列出每件等你拍板的事（合并、批准、几个方案里选一个），带着它的建议、证据和风险，让你光看回复就能做决定。

## 一晚上不止一件事

| 你手上的 | 用哪个剧本 | 一句话 |
| --- | --- | --- |
| 一队互不相干的 PR，要早上都合进去 | Autopilot-full | 每个 PR 一个负责人，一群新的验证者来验，**验过的才合** |
| 同上，但你想自己看过再合 | Autopilot-stack | 早上醒来是一排验证好的 PR，你自己审、自己合 |
| 一个要好几天的大项目 | Orchestrate | 一个常驻的协调者分派、检查，自己不写代码 |

<Copy id="autopilot" code="/poteto-mode 自动驾驶这五个改动，但别合并。我早上自己来合。" />

<Callout type="no" title="「做 4 个小时」不是完成条件">
时长给不了它任何可以检查的东西，你醒来只会看到四个小时的忙碌，而不是一个结果。给 `/loop` 一个能判断过或不过的条件。
</Callout>

## 卡住了？

<Q q="我不敢让它自己提交。">
<p>那就别写「提交之前不用问我」，或者用 Autopilot-stack，让它只做到验证完。等你看过几次它的决策日志、心里有数了，再放开。</p>
</Q>
<Q q="早上醒来发现它一直在原地打转。">
<p>多半是完成条件写得不够硬，或者验证工具不够。用 <code>/reflect</code> 把这次学到的记下来，用 <code>/correct</code> 把反复出现的失败变成检查。下一次会好很多。</p>
</Q>
