## 先确认它信得过

放手之前，这四条都要成立：

1. **你知道「好」长什么样**：自己做过一次，或看它做过一次。
2. **它有你会用的工具**：验证技能、日志。
3. **每一步都能证明自己**：达不到标准会停下。
4. **反复出的错已补上检查**：你读过几次对话记录。

<mark>四条都满足之前，就在你看着的时候跑。</mark>

## 睡前写一份交代

<Copy id="contract" title="睡前交代" code={`/poteto-mode 我要去睡了。在一个从 main 新开的 worktree 里，把所有调用方迁到新的解析器。
完成的标准：旧的调用方一个都不剩，所有解析器测试数据都通过，旧接口已删除。
记决策日志。提交之前不用问我。
/loop 直到完成。如果卡了几个小时真的走不下去，就停下来写清楚为什么。`} />

每一句的用处：

- **我要去睡了**：一直做，别再问我。
- **完成的标准**：每一轮都拿来检查。
- **新开的 <Term k="worktree" />**：另一份工作目录，不碰你手上的。
- **提交之前不用问我**：不会卡着等你点头。
- **/loop 直到完成**：反复检查做完没有（Cursor 和 Claude Code 自带）。
- **卡住就停下写原因**：停下比瞎忙八小时好。

<Callout type="no" title="「做 4 个小时」不是完成标准">
时长没法检查。给它一个能判断过或不过的标准。
</Callout>

## 早上：先看「需要注意」

<Copy id="audit" code="/show-me-your-work 把你昨晚做的事给我讲一遍" />

**你会得到**：一份总结。交回之前，另一个系列的模型会读一遍日志，在最后写「需要注意」。<strong>先读这一部分，再去看它指的那几行。</strong>

日志存在 `decisions.tsv`（几个任务共用一个目录时，在 `.audit/<任务名>.tsv`），默认只留在本机。

只想知道进展：在那个对话里打 `/ketchup`，它会说变了什么、哪些事等你拍板。

## 卡住了？

<Q q="我不敢让它自己提交。">
<p>删掉「提交之前不用问我」，或者用 Autopilot-stack，只做到验证完。</p>
</Q>
<Q q="早上发现它一直在原地打转。">
<p>多半是完成标准不够硬。用 <code>/reflect</code> 记下教训，用 <code>/correct</code> 把反复出的错变成检查。</p>
</Q>
<Q q="我想中途让它停下。">
<p>跟它说「暂停」或「我要下线了」。它会收好当前这一步，写一份续接说明，新对话能接着做。</p>
</Q>
