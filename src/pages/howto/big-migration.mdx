## 每一行管什么

- **「我去睡了」**：这次别停下来问你，一直做下去。
- **「完成的标准」**：每一轮都能跑一遍的检查。
- **「新 worktree」**：一个单独的工作区（<Term k="worktree" />），和你开着的其他工作互不干扰。
- **「提交之前不用问我」**：提前回答它本来会停下来问的问题。
- **`/loop until done`**：让它反复回来检查完成条件。`/loop` 是 Cursor 和 Claude Code 自带的命令，不是 pstack 的。
- **退路**：真卡死了就停下来写清原因，别硬撑一整夜。

<Callout type="no" title="时长不是完成条件">
「在这上面干 4 个小时」没法检查。给 <code>/loop</code> 一个能判断对错的条件。
</Callout>

## Chrome 插件的例子

几十个文件直接调用 `chrome.storage.sync`。你写好了新的 `settings` 模块，想把调用都迁过去，再删掉旧的 `getPref`。

<Copy id="mig-ext" title="Chrome 插件的例子" code={`/poteto-mode 我去睡了。在一个从 main 拉出来的新 worktree 里，把所有直接调用 chrome.storage.sync 的地方迁到新的 settings 模块。
完成的标准：
1. grep -rn "chrome.storage.sync" src/ 只剩 settings 模块里的那一处；
2. npm test 全部通过；
3. getPref 函数和它的测试已经删掉；
4. 用一个装过旧版本的测试 profile 打开选项页，所有设置读出来和迁移前一样，截图给我。
行为保持完全一致，迁移途中发现的 bug 记下来，不要顺手修。
记决策日志。提交之前不用问我。
/loop until done。如果真的卡死了，就停下来写清楚原因。`} />

- **四条完成标准**：一条 grep、一次测试、两个名字还在不在、一张截图。每条都能判断对错，早上你只看这四样。
- **「发现的 bug 不要顺手修」**：迁移前后才能直接对比。

## 放手之前，先确认它能自己检查

<mark>让它整晚自己跑，前提是它能自己检查自己的活。</mark>不然它只会更快地堆出没人查过的代码。四条都满足再放手：

1. **你做过一次。** 亲手做过，或看着 AI 做过，知道做好是什么样。
2. **工具它都有。** 你会用的<Term k="验证技能" />、profiler、日志。
3. **每一步都会自证。** 不达标时它能停下来。
4. **常犯的错已经补上。** 你读过它的对话记录，把反复出的错做成了检查。

没满足的话，就开着它跑，你在旁边看。

## 早上起来看哪里

<Copy id="mig-audit" title="早上审计" code="/show-me-your-work 告诉我你昨晚做了什么" />

**先读回复最后的 Attention。** 另一个模型家族的帮手 AI 会先读一遍日志。Attention 列出值得细看的地方，比如证据弱的决定。顺着它指的那几行去查就行。

<Term k="决策日志" />默认在工作目录的 `decisions.tsv`，不提交进仓库。每行一个决定，带理由和证据。

只想快速知道进度？在跑活的那个对话里打 `/ketchup`。它只看不改，告诉你变了什么、有哪些事等你拍板。

## 想中途停下

要合上电脑或重启编辑器，就明确说「暂停」或「我要下线了」。它会把没提交的改动提交成一个 `wip:` 提交，再写一份续做笔记。之后开一个新对话让它接手，它会从笔记接着做。

「继续」「keep going」不会让它暂停。

## 一晚上不止一件事

手上是一串改动，或者要跑好几天，有三种<Term k="剧本" />：

- **Autopilot-stack：不合并。** 早上你看到验证过的 PR，自己决定合不合。
- **Autopilot-full：会合并。** 每个 PR 要另一个帮手验证过才合。
- **Orchestrate：好几天的大项目。** 协调的那个自己不写代码。

拿不准就选 Autopilot-stack，合并前还有你这一关。

## 卡住了？

<Q q="早上它说「做完了」，我不确定。">
别信总结，看证据。把完成条件里的检查自己再跑一遍，比如那条 grep 和那次测试。再读 <code>/show-me-your-work</code> 回复里的 Attention。
</Q>
<Q q="它半夜停下来问我问题，白等了一晚。">
交代里缺了提前给的许可。下次写上「我去睡了」和「提交之前不用问我」。
</Q>
<Q q="它把完成条件改宽松了，然后宣布完成。">
它不该这样做。回它：「完成条件不变，原来的四条逐条跑给我看。」
</Q>
<Q q="我说了「继续」，它却做了个暂停提交。">
不应该发生。回它一句：「我没让你暂停，接着做。」
</Q>
