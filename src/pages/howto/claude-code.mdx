## 先装上

在 Claude Code 的对话框里，依次输入这两条：

<Copy id="cc-plugin" title="从插件市场装" code={`/plugin marketplace add cursor/plugins
/plugin install pstack@cursor-plugins`} />

装的是全套，`/poteto-mode` 要的东西都在。拿不准就用这个。

**想自己挑技能**，在终端里（不是对话框里）输入：

<Cmd c="npx skills add backnotprop/pstack" />

勾好技能，工具选 Claude Code，技能会放进 `.claude/skills/`。怎么挑看[只装几个技能](/howto/pick-skills/)。

## 命令前面加 pstack:

用插件市场装的，命令前要加插件名。教程里的 `/poteto-mode`，你要打成：

<Cmd c="/pstack:poteto-mode" />

其他命令也一样，比如 `/pstack:how`。本站其他页面都不写前缀，你自己补上。用 `npx skills` 装的不用加。

<Callout type="warn" title="技能不会自己跳出来">
除了 `setup-pstack`，每个技能都要你亲手打出来才运行。你说「帮我修个 bug」，它不会自己启用 `/pstack:poteto-mode`。
</Callout>

## 选模型，然后开新会话

装完先跑一次：

<Cmd c="/pstack:setup-pstack" />

它会问你<Term k="推理预算" />（让模型想多久），再给每个<Term k="模型角色" />配一个模型。最后写出一个文件：`~/.claude/rules/pstack-models.md`。

Claude Code 每次开新会话，都会读这个文件夹里的 `.md` 文件。所以<mark>跑完 setup，退出重开一个会话再干活</mark>。当前会话用的还是旧设置。

模型写成「名字 + 档位」，比如 `opus xhigh`。名字只有 `opus`、`sonnet`、`haiku`、`fable`。这些行放在这一个文件里就行，不要抄进 `CLAUDE.md`。

## 怎么配最好

**大多数人选「均衡」就行**：会话用 opus，写代码交给 sonnet。

为什么？两样东西决定用什么模型：

- **会话模型**：你用 `/model` 选的那个，就是你直接对话的 AI。它负责挑做法、派活、审每一份改动。
- **设置文件里的每一行**：派出去干活的帮手 AI（<Term k="子代理" />）各用什么模型。

pstack 默认让 grok 写代码。Claude Code 里用不了 grok，这些行就变成 `inherit-parent`，意思是跟着会话模型走。

所以什么都不改、会话又用 opus，所有活都是 opus 干的：花费最高，评审的两个座位也是同一个模型。均衡方案把写代码换成 sonnet，价钱减半，评审也有了两个模型。

价钱是 2026 年 10 月的 API 标价，每百万 <Term k="token" />。用订阅的话，贵的型号额度用得快：

| 型号 | 输入 / 输出 | 适合 |
| --- | --- | --- |
| fable | $10 / $50 | 最强，不计成本时用 |
| opus | $4 / $20 | 会话、做判断、最难的改动 |
| sonnet | $2 / $10 | 写代码、评审的第二个座位 |
| haiku | $0.1 / $0.5 | 不建议用 |

haiku 不建议用：检查结果也用写代码那一行的模型，换成最便宜的，检查也会变弱。

### 怎么写进去

1. 用 `/model` 选好会话模型。
2. 跑 `/pstack:setup-pstack`，预算按方案选。
3. 它问要不要改角色时，把上面的文件贴给它，让它照着写。
4. 退出，开一个新会话。

## 看到 Skipped in Claude Code

Cursor 的定时任务、Bugbot 审查机器人、云端代理，Claude Code 都没有。用到它们的步骤会被跳过，回复里留一行，然后接着做：

<Copy id="cc-skip" title="你会看到这样一行" code="Skipped in Claude Code: <哪一步>. <为什么跳过>." />

开 <Term k="PR" /> 不受影响，它会改用 `gh pr create`。`/loop` 这里也有。如果它说留了占位符（比如缺一个链接），看一眼缺什么，需要就自己补上。

## 打开自动更新

Claude Code 默认不更新第三方插件。打开自动更新：

1. 在对话框输入 `/plugin`。
2. 打开 **marketplaces** 标签页。
3. 选中 `cursor-plugins`。
4. 选 **enable auto-update**。

想手动更新，就跑：

<Cmd c="claude plugin update pstack@cursor-plugins" />

更新后默认模型变了，旧的设置文件还会用旧模型。处理办法看[更新、查看、卸载](/howto/update-remove/)。

## 卡住了？

<Q q="打 /poteto-mode 没反应，菜单里也找不到。">
插件市场装的，要打 `/pstack:poteto-mode`。先输入 `/pstack:`，菜单会只列出 pstack 的命令。
</Q>
<Q q="跑完 setup，换的模型没生效。">
设置文件只在新会话开始时读。退出重开一个会话。还不行，就打开 `~/.claude/rules/pstack-models.md`，看那一行是不是你选的模型。
</Q>
<Q q="回复说 /arena 跳过了评委，或者没找到别家的审阅者。">
有几步要求「另一家」的模型来审，比如 `/arena` 的评委。Claude 的模型都算同一家，所以它会跳过评委、自己挑，并说一声。`arena cross-judge pool` 那一行在这里基本用不上。想要别家的眼光，把要紧的评审拿到 Codex 或 Cursor 里再跑一次 `/interrogate`。
</Q>
<Q q="技能里写的是 Cursor 的叫法，要我自己换吗？">
不用，插件里带了对照说明（`docs/harness/claude-code.md`），AI 自己换算。比如 `.cursor/rules/` 改读 `CLAUDE.md`（没有就读 `AGENTS.md`），云端代理改成本地的 <Term k="worktree" />。
</Q>
<Q q="AI 说 Skill 工具调不动 pstack 的技能，坏了吗？">
没坏。在 Claude Code 里，大部分 pstack 技能本来就调不动。AI 会直接读那个技能的 `SKILL.md` 照着做。你照常打命令就行。
</Q>
<Q q="放它跑了一晚上，早上发现停在权限确认上。">
放手之前，先放行常用命令：git、gh、测试和构建命令。Claude Code 自带的 `/fewer-permission-prompts` 会找出你常用的只看不改的命令，写进项目的 `.claude/settings.json`。会改东西的命令，放不放你自己定。
</Q>
