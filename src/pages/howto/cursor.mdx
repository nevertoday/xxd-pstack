## 一条命令装好

在 Cursor 的对话框里输入：

<Cmd c="/add-plugin pstack" />

从侧边栏的 Customize 里装也一样。再选模型：

<Cmd c="/setup-pstack" />

它会问你<Term k="推理预算" />（让模型想多久），给每个<Term k="模型角色" />配一个模型，写进 `~/.cursor/rules/pstack-models.mdc`。

<Callout type="tip" title="跑完 setup，开一个新对话">
<u>这个设置只对新对话生效</u>。在旧对话里接着干，用的还是默认模型。
</Callout>

网站上的命令默认按 Claude Code 插件版写，前面带 `pstack:`，Cursor 里不用。在这里选 Cursor，全站的命令就会换成 Cursor 的写法，复制就能用：

<ToolPick />

## 从 / 菜单选 /poteto-mode

先在对话框打 `/`，从菜单里选中 `/poteto-mode`，再写任务：

<Copy id="cursor-first" title="第一个任务" code="/poteto-mode 给这个命令加一个 --json 参数。原来的文字输出要和现在逐字一样。两种输出都验证一下。" />

发送时按哪个键，结果不一样：

- **Enter**：只管这一条消息。聊几轮，它就不灵了。
- **Option+Enter（Mac）或 Alt+Enter（Windows）**：<mark>变成 <Term k="Custom Mode" />，之后每一轮都生效</mark>，直到你退出这个模式。

开了 Custom Mode，后面说「do it」「continue」就够了。

做完一件事要换下一件，开头先说「new task」。不说的话，它会把新问题当成上一件事的下一步。

## 睡觉前交给它：/loop

`/loop` 是 Cursor 自带的命令，让 AI 隔一会儿醒来检查做完没有。要给它一个能判断过没过的完成条件：

<Copy id="cursor-loop" title="睡前交代" code={`/poteto-mode 我去睡了。在一个新的 worktree 里（从 <你的基础分支> 拉出来），把所有调用方迁到新的解析器。
做完的标准：旧调用方一个都不剩，所有解析器测试数据都通过，旧 API 删掉。
记决策日志。提交之前不用问我。
/loop until done。如果几个小时后真的卡死了，停下来，写清楚为什么。`} />

「干 4 小时」不算完成条件。它没东西可检查，你醒来只会看到 4 小时的忙碌。更完整的写法看[放手让它跑](/guide/7-overnight/)。

## 几个 AI 同时干活：各用各的地方

几个 AI 在同一个文件夹里改代码，会互相覆盖。两种分开的办法：

- **云端：** 在任务前面打 `/in-cloud`。每个 AI 有自己的机器和分支，不碰你的电脑。
- **本地：** 每个任务开一个自己的 <Term k="worktree" />（同一个仓库的另一份工作目录）。笔记本上一次开几个就够了。

<Copy id="cursor-wt" code={`/poteto-mode new task. 从 <基础分支> 拉一个新的 worktree，在那里把解析器的改动移植过去。`} />

## 有几样要另外装

`/poteto-mode` 有几步会用到 `cursor-team-kit` 插件。没装也能跑，只是那一步做得差一点。想要全套就装上它，里面有：

- **`deslop`**：清掉代码里的「AI 味」。
- **`control-cli`**：操作命令行程序。
- **`control-ui`**：操作浏览器和网页。

另外，pstack 没有做计划的技能，可以配合 Cursor 自带的 Plan Mode。

## 卡住了？

<Q q="/poteto-mode 用了几轮就不灵了。">
你多半是按 Enter 发的。重新从菜单选它，按 Option+Enter（Windows 是 Alt+Enter）。或者每个新任务都重新打一次 `/poteto-mode`。
</Q>
<Q q="改了模型设置，跑起来还是原来的模型。">
设置只对新对话生效。开一个新对话再试。
</Q>
<Q q="几个 AI 同时干活，把文件改乱了。">
给每个任务开自己的 worktree，或者用 `/in-cloud` 交给云端。
</Q>
<Q q="开了 /loop 一晚上，什么都没做完。">
完成条件要能判断过没过，比如「这个命令返回 0」「这些测试全过」。「干到早上」不算。
</Q>
<Q q="听说 pstack 带了一个叫 benny 的自动化包？">
有，默认不启用。它会分拣 Slack 里报的问题，把确认是 bug 的修好。要启用，把 Cursor 指到 benny 目录里的 `FOR_AGENTS.md`。
</Q>
