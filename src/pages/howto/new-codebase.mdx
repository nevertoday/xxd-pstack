## 先照抄一个

<Copy id="nc-first" title="第一句" code="/poteto-mode 带我看懂这个项目：它是做什么的、怎么在本地跑起来、主要的代码在哪。告诉我你看了哪些文件、用了哪些资料。先不要改任何代码。" />

- **「先不要改任何代码」**：<mark><strong>没看懂之前，它只看不改。</strong></mark>它只做调查，不开 <Term k="PR" />。
- **「告诉我看了哪些文件」**：它会把读到的和推出来的分开写。

## 发出去以后看哪里

交回来的是一份说明，每条都写着出处。通常分这几块：

- **概览**：项目是做什么的。
- **关键概念和怎么工作。**
- **东西放在哪。**
- **容易踩的坑。**

## 再问细节：四个命令

| 命令 | 问什么 | 例子 |
| --- | --- | --- |
| `/how` | 现在怎么工作 | 通知怎么去重？ |
| `/why` | 当初为什么这样写 | 重试上限为什么是 5？ |
| `/teach` | 讲到你真懂 | 教我这次重试的改动 |
| `/recall` | 你之前做到哪了 | 导出功能做到哪了？ |

- **`/why`** 先查 Git 历史，再查 issue、文档这些。查不到会直说。「没人写下原因」本身也是答案。
- **`/teach`** 加一句「说服我」，讲解就变成一个你能检验的论证。
- **`/recall`** 只翻你自己在这个项目里的记录，默认看最近 7 天。

## 会员站的例子

朋友交给你一个 Cloudflare Workers 会员站，数据在 D1 里。你要改会员到期的逻辑。先用上面第一句摸全局，再顺着问：

<Copy id="nc-how" title="先问现在怎么工作" code="/how 用户登录以后，会员身份是怎么一路传到页面上的？session 存在哪？会员到期是在哪里判断的？" />

<Copy id="nc-why" title="再问为什么" code="/why 为什么会员到期判断在两个地方各写了一遍？这个理由现在还成立吗？" />

<Copy id="nc-teach" title="最后讲到你真懂" code="/teach 我要改会员到期的逻辑。教我这一块是怎么工作的，说服我只改一个地方不会让已经付费的用户被踢出去。" />

三个问完再让它动手。这时你和它心里是同一张图。

## 接手一个做了一半的分支

上周的你，或者另一个 AI 对话，在一个分支上做到一半。发这句：

<Copy id="nc-pickup" title="接着做" code="/poteto-mode 接手这个分支。读决策日志，弄清哪些已经做完，从那里接着做。已经做完的不要重做。" />

它会找到之前的记录（对话、分支、<Term k="决策日志" />），说出从哪一步接着做。前一个对话说「通过了」，它会自己再查一遍。

<Callout type="tip" title="/recall 和接手分支别搞混">
接着做一个具体的对话，用上面这句。开始新活之前，想找回最近几次对话的来龙去脉，用 <code>/recall</code>。比如：「/recall 我昨天做虚拟列表的那些工作，然后读一下这个 bug 报告。」
</Callout>

## 卡住了？

<Q q="说了先别改，它还是改了代码。">
同一个对话里换新问题，开头加「new task」：「/poteto-mode new task. 弄清楚为什么退出登录后缓存还在。先不要改任何代码。」不说的话，它会把你的问题当成上一件事的下一步。
</Q>
<Q q="/why 说查不到当初的原因。">
这是正常结果。你知道答案可能在哪，比如一个 issue 链接或一份旧文档，直接贴给它。
</Q>
<Q q="讲得很全，但我没看懂。">
打 <code>/bro</code>，它会把上一条用大白话重说一遍，更短。
</Q>
<Q q="接手分支时，它把做过的又从头做了一遍。">
回它：「之前的记录是可信的，不要从头重来。说出从哪一步接着做。」
</Q>
<Q q="在 Claude Code 里打这些命令没反应。">
以插件方式装的，命令前要加 <code>pstack:</code>，比如 <code>/pstack:poteto-mode</code>、<code>/pstack:how</code>。详见<a href="/howto/claude-code/">在 Claude Code 里用</a>。
</Q>
