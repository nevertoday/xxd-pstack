## 先照抄一个

<Copy id="rv-int" title="评审整个分支" code="/interrogate 整个分支，挑剔一点。先别改任何东西。不是真 bug、不是行为回退的小毛病不要报。" />

- **「先别改任何东西」**：它只看不改。
- **「小毛病不要报」**：命名、风格这类意见提前滤掉。

写代码的 AI 很难看出自己的毛病。所以换几个模型来挑：<mark><strong>它们专门去把改动弄坏，每个问题都要真跑出来才算数。</strong></mark>用的是你在 `/setup-pstack` 里配的模型。

## 发出去以后看哪里

它只报告，不改你的代码。报告分三块：

- **Intent**：它理解的这次改动想做什么。理解错了，后面都不用看。
- **Findings**：复核通过的问题。每条都带命令和输出，它自己重跑过。
- **Dropped**：被丢掉的，和丢掉的理由。

<Callout type="warn" title="Dropped 也扫一眼">
被丢掉只说明没能用一次运行证明，不一定不是问题。你觉得哪条被冤枉了，可以让它补一个复现。
</Callout>

## 只改了几行，还是不放心：/blast-radius

它不列一长串「可能的风险」。它找出这个改动安全靠的是哪一个事实，再写一段真代码去证明。证明不了的，标「unproven」。

比如你在 Chrome 插件里，把收藏从 `chrome.storage.sync` 挪到了 `chrome.storage.local`。担心老用户升级后收藏没了：

<Copy id="rv-blast" title="Chrome 插件的例子" code={`/blast-radius 这个分支把收藏从 chrome.storage.sync 挪到了 chrome.storage.local。
我最担心的是：老用户升级以后，原来存在 sync 里的收藏还在不在。
找出这个改动安全靠的是哪个事实，写一段脚本真跑一遍证明它，把输出贴给我。`} />

好的结果：关键事实是「升级后第一次启动，会把旧收藏搬到 local」。再写个脚本：放三条假收藏，模拟升级，看 local 里是不是正好三条。

它只交回「经分析，此改动是安全的」？回它：「把那个事实证明到能跑的级别。」

## 提交前清理注释和文字

- **`/no-comments`**：删掉多余的注释。只留许可证头、公开接口的说明、代码表达不了的外部链接、被外部依赖逼出来的写法。
- **`/unslop`**：去掉 PR 说明和提交信息里的 AI 腔。可以加你的规矩，比如 `/unslop PR 说明，不要用破折号`。

<Callout type="no" title="/deslop 不在 pstack 里">
pstack 文档里常出现的 <code>/deslop</code> 来自 Cursor 的另一个插件包。没装的话，直接说：「删掉描述代码在干什么的注释、没有依据的防御判断、已经用不上的兼容代码、和这次任务无关的改动。」
</Callout>

## PR 开了以后：交给 Babysit

<Term k="PR" /> 一开，检查会挂、有人留评论、主分支往前走。这些交给它盯：

<Copy id="rv-babysit" title="盯到可以合并" code="/poteto-mode babysit 这个 PR，把它弄绿。" />

它先处理冲突，再处理评论，最后处理检查。只想知道现在什么情况，就问：「/poteto-mode 看一下 PR 123，还有什么没处理的？」

<Callout type="warn" title="全绿了它也不会合并">
它停在「可以合并」。要合并，你得明确说「land the stack」或「合并吧」。
</Callout>

## 卡住了？

<Q q="/interrogate 说「no verified findings」，是它偷懒了吗？">
这是正常结果。看一眼 Dropped。你有具体的怀疑，就说出来，让它针对那一点去试。
</Q>
<Q q="我觉得被丢掉的某一条是真问题。">
回它：「Dropped 里第二个对手说的那条，写一个复现给我看。」跑出来了，就是真问题。
</Q>
<Q q="Babysit 全绿了，怎么还不合并？">
这是故意的。说「land the stack」或「合并吧」，它会先让没写过代码的帮手逐个验证 PR，再从最底下开始合并。
</Q>
<Q q="/no-comments 把我想留的注释删了。">
它只留讲「我们改不了的东西」的注释。觉得删错了，告诉它这条注释在讲哪个外部限制，让它重新判断。
</Q>
<Q q="在 Claude Code 里打这些命令没反应。">
以插件方式装的，命令前要加 <code>pstack:</code>，比如 <code>/pstack:interrogate</code>。详见<a href="/howto/claude-code/">在 Claude Code 里用</a>。
</Q>
