## 先想想你当初是怎么装的

更新和卸载的办法，取决于你当初走的哪条路：

| 当初输入的是 | 属于 |
| --- | --- |
| `npx skills add backnotprop/pstack` | skills 命令行 |
| `/plugin install pstack@cursor-plugins` | Claude Code 插件 |
| `/add-plugin pstack` | Cursor 插件 |

记不清了？用 skills 命令行装的，技能会出现在 `.claude/skills/`、`.agents/skills/` 这类文件夹里，每个技能一个子文件夹。用 Claude Code 插件装的，命令要带 `pstack:` 前缀，比如 `/pstack:poteto-mode`。

## 更新以后：旧设置还钉着旧默认

这是更新时最容易踩的坑。

`/setup-pstack` 写的设置文件，会把每个<Term k="模型角色" />用的模型一行一行写死。如果新版本 pstack 换了默认模型，你的旧文件里写的还是**旧的默认值**。<mark>技能读到这一行，就照旧用旧模型，新默认对你不生效</mark>。

解决办法，二选一：

1. 打开设置文件，删掉那些你没特意改过、只是当时照默认写进去的角色行。删掉的角色会回到技能的新默认。
2. 直接把整个文件删了，再跑一次 `/setup-pstack`。

设置文件在哪，看你用的工具：

| 工具 | 设置文件 |
| --- | --- |
| Cursor | `~/.cursor/rules/pstack-models.mdc` |
| Claude Code | `~/.claude/rules/pstack-models.md` |
| Codex 和其他工具 | `~/.agents/pstack-models.md` |

<Callout type="ok" title="重跑不会冲掉你改过的">
重跑 `/setup-pstack` 时，模型和默认值不一样的角色（就是你特意改过的）会被保留。所以放心重跑。重跑还会顺手删掉已经废弃的角色行，并告诉你删了哪些。
</Callout>

改完同样要开一个新对话（Cursor 和 Claude Code）才生效。

## 卸载以后：设置文件还在

卸载技能或插件，不会顺手删掉你的模型设置文件。在 Claude Code 里要特别注意：它会把 `~/.claude/rules/` 里所有的 `.md` 文件读进每一个新会话。卸了 pstack 但留着 `pstack-models.md`，这些角色行还是会出现在每个会话里，白占地方。

彻底不用了，就把上面表里对应的那个文件也删掉。

另外，如果你当时让 `/setup-pstack` 生成过<Term k="验证技能" />（项目里的 `verify-你的应用` 这类文件夹），它属于你的项目，不会跟着 pstack 一起卸掉。还想用就留着，不想要就自己删。

## 卡住了？

<Q q="更新完了，跑起来用的还是老模型。">
多半就是上面说的旧设置文件。打开它看看那个角色的行，删掉或者重跑 `/setup-pstack`。然后开一个新对话。
</Q>
<Q q="Claude Code 里的 pstack 一直不更新。">
第三方插件市场默认不自动更新。手动跑 `claude plugin update pstack@cursor-plugins`，或者在 `/plugin` 的 marketplaces 标签页里给 `cursor-plugins` 打开自动更新。
</Q>
<Q q="npx skills list 里看不到 pstack 的技能。">
确认你是在当初安装的那个项目文件夹里运行的。用 `-g` 装到用户目录的，和装在项目里的，是两份不同的位置。
</Q>
