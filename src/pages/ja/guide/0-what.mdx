## pstack とは

pstack は、<Term k="技能" text="スキル" />をまとめたパックです。普段使っている Claude Code、Cursor、Codex などの AI コーディングツールに入れて使います。

これを入れると、AI はシニアエンジニアのルールに沿ってコードを書くようになります：<mark><strong>まず理解し、それから手を動かし、最後に自分で確かめる。</strong></mark>

モデルはそのままです。変わるのは、作業の順番と合格ラインです。

## どんな悪いクセを直すのか

- **理解していないコードを変えてしまう**。それっぽいけれど違う場所を編集してしまいます。
- **表面上の症状だけに対処する**。重複データを表示の側で隠してしまいます。重複を生んでいるバグ自体はそのまま残ります。
- **試さずに「完了」と言う**。「もう大丈夫なはずです」と言います。実際に動かすと、まだ壊れたままです。
- **変更がどんどん膨らむ**。誰も必要としないコードを追加してしまい、そこに次のバグが潜みます。

## 使うコマンドは 1 つだけ

普段は `/poteto-mode` と入力するだけです。ゴールを伝えれば、あとは自動で計画を立ててくれます。裏側にはさらにいろいろな仕組みがありますが、今は覚える必要はありません：

- **<Term k="剧本" text="プレイブック" /> 22 個**：バグ修正、機能追加、リファクタリング…作業の種類ごとに 1 つずつ進め方があります。
- **スキル 34 個**：たとえば `/how` はコードを解説し、`/bro` はわかりやすい言葉に言い換えてくれます。詳しくは[スキル一覧](/ja/skills/)をご覧ください。
- **<Term k="原则" text="原則" /> 24 個**：たとえば「subtract before you add（足す前に引く）」や「prove it works（動くことを証明する）」などがあります。
- **ヘルパーの AI 2 つ**：1 つは作業を任されたときも同じルールに沿って動き、もう 1 つはコメントだけをレビューします。

## 得られること

- **変更は小さく、毎回ちゃんと試す**。消せるものは消し、最後に実際のコマンドを実行し、実際の UI をクリックします。
- **複数の AI を同時に動かせる**。それぞれが同じルールを守り、自分専用のフォルダで作業します。
- **同じミスを繰り返さない**。`/correct` を使えば、根本から防げます。

<Callout type="warn" title="コスト：遅くなり、料金も高くなる">
ヘルパーの AI を多く動かし、複数のモデルどうしでチェックし合います。そのため時間がかかり、トークン消費も増えます。小さな変更では使わなくて大丈夫です。節約したいときは、[コストを抑える](/ja/howto/cost/)をご覧ください。
</Callout>

## 4 つのものを用意しておく

- **AI コーディングツール**：Claude Code、Cursor、Codex のいずれか 1 つ（OpenCode や Pi でも使えます）。コードを書き換えてコマンドを実行できるツールが必要です。<u>ブラウザ上でチャットするだけの AI は使えません</u>。
- **使えるモデル**：ツールの有料プラン、または API キー。
- **Git 管理された実際のプロジェクト**：ほとんどのプレイブックは <Term k="worktree" />（同じ Git リポジトリの別作業フォルダ）を作成し、<Term k="PR" /> を開きます。まだ Git を使っていませんか？まずは `git init` を実行して、1 回コミットしておきましょう。
- **Node.js 22.20 以降**：`npx skills` でインストールする場合のみ必要です。
