## コマンド 1 つでインストール

Cursor のチャット入力欄に、次のように入力します。

<Cmd c="/add-plugin pstack" />

サイドバーの「Customize」からインストールしても同じです。続けて、使うモデルを選びます。

<Cmd c="/setup-pstack" />

このコマンドは<Term k="推理预算" />（モデルがどれくらい長く考えるか）を尋ね、<Term k="模型角色" />ごとにモデルを割り当てて、`~/.cursor/rules/pstack-models.mdc` に書き込みます。

<Callout type="tip" title="セットアップ後は新しい会話を始めてください">
<u>この設定は新しい会話にのみ適用されます</u>。以前の会話をそのまま続けると、デフォルトのモデルが使われたままになります。
</Callout>

このサイトのコマンドは、デフォルトでは Claude Code プラグイン向けに書かれています。先頭に付いている `pstack:` は、Cursor では使いません。ここで Cursor を選ぶと、サイト内のすべてのコマンドが Cursor の書き方に切り替わり、そのままコピーできるようになります。

<ToolPick />

## / メニューから /poteto-mode を選ぶ

チャット入力欄で `/` を入力し、メニューから `/poteto-mode` を選んでからタスクを書きます。

<Copy id="cursor-first" title="最初のタスク" code="/poteto-mode このコマンドに --json フラグを追加してください。既存のテキスト出力は 1 バイトも変わらないようにしてください。両方の出力を検証してください。" />

どのキーで送信するかによって挙動が変わります。

- **Enter**：この 1 通のメッセージだけに効きます。数ターン後には効かなくなります。
- **Option+Enter（Mac）または Alt+Enter（Windows）**：<mark><Term k="Custom Mode" />（Cursor のカスタムモード）になり、毎ターン有効なまま</mark>、モードを抜けるまで続きます。

Custom Mode がオンになっていれば、それ以降のメッセージは「進めて」や「続けて」だけで足ります。

1 つの作業を終えて次に移るときは、「新しいタスク」と最初に伝えてください。そうしないと、新しい質問を前の作業の続きとみなしてしまいます。

## 寝る前に任せる：/loop

`/loop` は Cursor の組み込みコマンドです。ときどき AI を起こして、作業が終わったかどうかを確かめます。成功か失敗かがはっきり判定できる完了条件を渡してください。

<Copy id="cursor-loop" title="寝る前に" code={`/poteto-mode これから寝ます。新しい worktree（<ベースブランチ> から分岐）で、すべての呼び出し元を新しいパーサーに移行してください。
完了条件：古い呼び出し元が 1 つも残っていないこと、パーサーのテストデータがすべて通ること、古い API が削除されていること。
判断ログを残してください。コミット前に確認しなくて構いません。
/loop until done。数時間たっても本当に行き詰まったら、止めて理由を書き残してください。`} />

「4 時間作業する」は完了条件になりません。確かめるものがないため、朝起きても 4 時間分の空回りした作業が残るだけです。詳しい内容は、[任せて走らせる](/ja/guide/7-overnight/)をご覧ください。

## 複数の AI を同時に動かす：それぞれに別の場所を用意する

複数の AI が同じフォルダでコードを変えると、お互いの変更を上書きしてしまいます。分ける方法は 2 つあります。

- **クラウドで動かす**：タスクの前に `/in-cloud` と入力します。AI ごとに専用のマシンとブランチが割り当てられ、手元のパソコンには影響しません。
- **ローカルで動かす**：タスクごとに専用の <Term k="worktree" />（同じ Git リポジトリの別作業フォルダ）を割り当てます。ノート PC なら、同時に数個で十分です。

<Copy id="cursor-wt" code={`/poteto-mode new task. <ベースブランチ> から新しい worktree を作り、パーサーの変更をそちらに移植してください。`} />

## 別途インストールするもの

`/poteto-mode` の一部の手順では、`cursor-team-kit` プラグインを使います。入れなくても動きますが、その手順の働きが弱くなります。フルセットで使うならインストールしてください。以下が含まれています。

- **`deslop`**：コードから「AI っぽさ」を取り除きます。
- **`control-cli`**：コマンドラインのプログラムを操作します。
- **`control-ui`**：ブラウザや Web ページを操作します。

pstack には計画を立てるスキルがありません。Cursor 組み込みの Plan Mode を併用してください。

## つまずいたときは？

<Q q="/poteto-mode が数ターンで効かなくなります。">
Enter で送信した可能性が高いです。メニューからもう一度選び、Option+Enter（Windows では Alt+Enter）を押してください。あるいは、新しいタスクごとに `/poteto-mode` を入力し直してください。
</Q>
<Q q="モデル設定を変えたのに、古いモデルのまま動いています。">
設定は新しい会話にしか適用されません。新しい会話を始めて、もう一度試してください。
</Q>
<Q q="複数の AI を同時に動かしたら、ファイルがぐちゃぐちゃになりました。">
タスクごとに専用の worktree を割り当てるか、`/in-cloud` でクラウドに任せてください。
</Q>
<Q q="/loop を一晩中回したのに、何も終わっていませんでした。">
完了条件は、「このコマンドが 0 を返す」「これらのテストがすべて通る」のように、成功か失敗かを判定できるものにしてください。「朝まで作業する」は条件になりません。
</Q>
<Q q="pstack には benny という自動化パックが付いているのですか？">
はい、付いていますがデフォルトではオフです。Slack で報告された問題を仕分けし、バグと確認されたものを修正します。有効にするには、benny フォルダにある `FOR_AGENTS.md` を Cursor に参照させてください。
</Q>
