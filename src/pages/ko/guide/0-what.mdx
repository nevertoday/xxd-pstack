## pstack은 무엇인가요?

pstack은 <Term k="技能" text="스킬" /> 묶음이에요. Claude Code, Cursor, Codex처럼 이미 쓰고 있는 AI 코딩 도구에 넣어서 써요.

넣고 나면 AI가 시니어 엔지니어의 규칙대로 코드를 써요. <mark><strong>먼저 이해하고, 그다음에 작업하고, 마지막으로 스스로 확인해요.</strong></mark>

모델은 그대로예요. 달라지는 건 일하는 순서와 통과해야 하는 기준이에요.

## 어떤 나쁜 습관을 고쳐 주나요?

- **이해하지 못한 코드부터 고치기**. 그럴듯해 보이지만 틀린 곳을 수정해요.
- **증상만 처리하기**. 화면에 보이는 곳에서만 중복 데이터를 숨겨요. 중복을 만드는 버그는 그대로 남아 있어요.
- **해 보지도 않고 “완료”라고 하기**. “이제 괜찮을 거예요”라고 해요. 막상 돌려 보면 여전히 안 돼요.
- **수정 범위가 자꾸 커지기**. 아무에게도 필요 없는 코드를 덧붙이고, 다음 버그가 그 안에 숨어요.

## 명령어는 하나만 알면 돼요

평소에는 `/poteto-mode`만 입력하면 돼요. 목표를 말하면 나머지는 알아서 계획을 세워요. 그 뒤에는 더 많은 것들이 있지만, 아직은 익히지 않아도 돼요.

- **<Term k="剧本" text="플레이북" /> 22개**: 버그 수정, 기능 추가, 리팩터링… 작업 종류마다 정해진 방식이 하나씩 있어요.
- **스킬 34개**: 예를 들어 `/how`는 코드를 설명해 주고, `/bro`는 쉬운 말로 풀어 줘요. [스킬 목록](/ko/skills/)을 참고하세요.
- **<Term k="原则" text="원칙" /> 24개**: 예를 들어 “subtract before you add”(더하기 전에 빼기)와 “prove it works”(작동하는 걸 증명하기) 같은 원칙이에요.
- **도우미 AI 2개**: 하나는 따로 일을 맡겼을 때 같은 규칙대로 일하고, 다른 하나는 코멘트만 검토해요.

## 쓰면 무엇이 좋아지나요?

- **더 작게 고치고, 매번 직접 확인해요**. 지울 수 있는 건 지우고, 마지막에는 실제 명령어를 돌리고 실제 UI를 클릭해 봐요.
- **AI를 여러 개 동시에 돌릴 수 있어요**. 각자 같은 규칙을 따르면서 자기만의 폴더에서 작업해요.
- **같은 실수는 두 번 반복되지 않아요**. `/correct`로 근본부터 막을 수 있어요.

<Callout type="warn" title="대가: 더 느리고 비싸요">
도우미 AI를 더 많이 불러 쓰고, 여러 모델이 서로 확인하게 해요. 그래서 더 느리고 토큰도 더 많이 써요. 작은 수정에는 건너뛰세요. 비용을 아끼려면 [비용 관리하기](/ko/howto/cost/)를 보세요.
</Callout>

## 네 가지를 준비하세요

- **AI 코딩 도구**: Claude Code, Cursor, Codex 중 하나면 돼요(OpenCode와 Pi도 돼요). 코드를 직접 고치고 명령어를 돌릴 수 있어야 해요. <u>브라우저에서 대화만 하는 AI는 안 돼요</u>.
- **쓸 수 있는 모델**: 도구의 유료 플랜이나 API 키가 있으면 돼요.
- **Git으로 관리하는 실제 프로젝트**: 대부분의 플레이북은 <Term k="worktree" />(워크트리, 같은 Git 저장소의 별도 작업 폴더)를 만들고 <Term k="PR" />을 열어요. 아직 Git을 안 쓰고 있나요? 먼저 `git init`을 실행하고 커밋을 하나 만드세요.
- **Node.js 22.20 이상**: `npx skills`로 설치할 때만 필요해요.
