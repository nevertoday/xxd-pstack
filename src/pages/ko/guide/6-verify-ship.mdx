## 첫 문장에서 무엇이 완료인지 말하기

<Copy id="done" code="/poteto-mode 이 명령어에 JSON 출력을 추가해 주세요. 텍스트 출력은 바이트 단위로 똑같이 유지돼야 하고, JSON은 파싱돼야 해요. 둘 다 예제 프로젝트에서 실행하고 근거를 보여 주세요." />

답변에는 실제 명령어와 그 출력이 들어 있어야 해요. 확인을 돌리지 못했다면 “판단 불가(inconclusive)”라고 나와요.

<mark><strong>“컴파일된다”는 말은 증명이 아니에요.</strong></mark> 변경 내용에 맞는 근거를 요청하세요.

| 바뀐 내용 | 요청할 근거 |
| --- | --- |
| 명령줄 | 실제 명령어 실행하기 |
| UI | 실행 중인 앱에서 직접 조작해 보기 |
| 파서, 마이그레이션 | 저장해 둔 입력 다시 돌려 보기 |
| 성능 | 전후 측정값 비교하기 |
| 스토리지 | 기록한 값 다시 읽어 오기 |

## AI가 앱에서 직접 검증하게 하기

AI가 앱을 직접 조작할 방법이 없다면 이것부터 실행하세요.

<Copy id="cvs" code="/create-verification-skill" />

**결과**: `/verify-<your-app-name>` <Term k="验证技能" />이 만들어져요. 주로 코드를 읽고, 넘겨주기 전에 전체 시범 실행을 한 번 돌려요. <u>시범 실행이 실패했다면 만들어진 것을 쓰지 마세요.</u>

그다음에는 이렇게 근거를 요청하세요.

<Copy id="use-vs" code="/poteto-mode 일괄 보관 기능을 만들어 주세요. /verify-<your-app-name>으로 검증하고, 화면 녹화와 스크린샷을 근거로 보여 주세요." />

이 검증 스킬은 저장소에 커밋해 두세요. `/maintain-verification-skill`로 정기적으로 점검하세요(매일이 가장 좋아요). 무엇이 만들어지는지, 어떻게 확인하는지, 작성자가 어떻게 쓰는지는 [프로젝트에 검증 스킬 만들어 주기](/ko/howto/verify-app/)를 참고하세요.

## PR 올리기

<Term k="PR" />은 리뷰를 받기 위해 보낸 뒤 머지하는 변경 묶음이에요.

<Copy id="pr" code="/poteto-mode PR을 올려 주세요. 커밋은 작고 순서대로 나누고, 설명에 근거를 넣어 주세요." />

**결과**: <Term k="worktree" />(워크트리, 같은 Git 저장소의 별도 작업 폴더)에서 커밋을 작게 나누어 정리하고, 마지막에 PR 링크를 알려 줘요.

## 머지할 준비하기: babysit(PR·CI 돌보기)

<Copy id="babysit" code="/poteto-mode 이 PR을 babysit해서 모든 체크를 통과시켜 주세요." />

**결과**: 충돌을 먼저 해결하고, 그다음 리뷰 코멘트, 그다음 CI(푸시할 때마다 돌아가는 검사) 순으로 처리해요. 진짜 문제는 고쳐요. 타당하지 않은 코멘트에는 이유를 적어 답장해요.

<strong>“머지할 준비 완료” 단계에서 멈춰요. 절대 대신 머지하지 않아요.</strong>

## 머지하기: land the stack

스택(PR 스택)은 서로 위에 이어서 쌓은 여러 PR 묶음이에요.

<Copy id="ship" code="/poteto-mode land the stack." />

**결과**: 각 PR을 직접 작성하지 않은 AI가 다시 검증해요. 맨 아래부터 시작해서 끊기지 않고 연속으로 통과한 PR만 머지해요. 체인이 어디서 끊겼는지 알려 줘요.

<Callout type="tip" title="Claude Code를 쓰고 있다면">
PR을 올릴 때 `gh`를 써요. 먼저 내 컴퓨터에서 `gh auth login`으로 GitHub에 로그인하세요.
</Callout>
