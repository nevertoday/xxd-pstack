## 각 줄이 하는 일

- **“자러 갈게요”**: 멈춰서 묻지 말고 계속하라는 뜻이에요.
- **“완료 조건”**: 매 라운드마다 스스로 돌려 볼 수 있는 확인 기준이에요.
- **“새 worktree”**: 같은 Git 저장소의 별도 작업 폴더(<Term k="worktree" />, 워크트리)예요. 열려 있는 다른 작업을 건드리지 않아요.
- **“커밋 전에 물어보지 않아도 돼요”**: 물어보려고 멈출 만한 질문을 미리 답해 두는 거예요.
- **`/loop until done`**: 완료 조건을 계속 다시 확인하게 만들어요. `/loop`는 Cursor와 Claude Code에 기본 내장된 기능이에요. pstack 스킬이 아니에요.
- **탈출구**: 정말 막히면 밤새 헛돌지 않고 멈춰서 이유를 설명해요.

<Callout type="no" title="들인 시간은 완료 조건이 아니에요">
“4시간 동안 작업해 주세요”에는 확인할 기준이 없어요. <code>/loop</code>에는 통과와 실패가 갈리는 조건을 주세요.
</Callout>

## Chrome 확장 프로그램 예시

수십 개 파일이 `chrome.storage.sync`를 직접 호출하고 있어요. 새 `settings` 모듈을 만들었고, 모든 호출을 그쪽으로 옮긴 뒤 기존 `getPref`를 삭제하려고 해요.

<Copy id="mig-ext" title="Chrome 확장 프로그램 예시" code={`/poteto-mode 자러 갈게요. main에서 새 worktree를 만들어 chrome.storage.sync를 직접 호출하는 코드를 모두 새 settings 모듈로 옮겨 주세요.
완료 조건:
1. grep -rn "chrome.storage.sync" src/ 결과에 settings 모듈 안의 호출 한 곳만 남아 있어야 해요.
2. npm test가 전부 통과해야 해요.
3. getPref 함수와 관련 테스트가 삭제되어 있어야 해요.
4. 이전 버전이 설치된 테스트 프로필로 옵션 페이지를 열었을 때 모든 설정이 마이그레이션 전과 똑같이 보여야 해요. 스크린샷을 보내 주세요.
동작은 완전히 똑같이 유지하세요. 마이그레이션 중에 버그를 발견하면 메모만 남겨 두세요. 중간에 고치지 마세요.
결정 로그를 남겨 주세요. 커밋 전에 물어보지 않아도 돼요.

- **완료 조건 네 가지**: grep 한 번, 테스트 실행 한 번, 이름 두 개가 남아 있는지 확인, 스크린샷 한 장이에요. 하나하나 통과 아니면 실패예요. 아침에는 이 네 가지만 확인하면 돼요.
- **“중간에 버그를 고치지 마세요”**: 전후를 바로 비교하기 위해서예요.

## 손을 떼기 전에: 스스로 확인할 수 있나요?

<mark>AI가 스스로 작업을 확인할 수 있을 때만 밤새 돌려 두는 방식이 통해요.</mark> 그렇지 않으면 확인 안 된 코드만 더 빠르게 쌓일 뿐이에요. 네 가지가 모두 맞을 때만 손을 떼세요:

1. **한 번은 직접 해 봤어요**. 손으로 했든, AI가 하는 걸 지켜봤든 좋아요. 완료된 모습이 어떤지 알고 있어요.
2. **도구가 갖춰져 있어요**. 직접 쓰는 <Term k="验证技能" />, 프로파일러, 로그예요.
3. **단계마다 스스로 증명해요**. 한 단계가 기준에 못 미치면 멈출 수 있어요.
4. **반복되는 실수를 막아 뒀어요**. 대화 기록을 읽어 보고, 반복되는 오류를 확인 항목으로 만들어 뒀어요.

그렇지 않다면 지켜보면서 돌리세요.

## 아침에 확인할 곳

<Copy id="mig-audit" title="아침 점검" code="/show-me-your-work 어젯밤에 뭘 했는지 알려 주세요" />

**끝에 나오는 Attention 섹션부터 읽으세요**. 다른 회사 모델로 돌아가는 도우미 AI가 로그를 먼저 읽어요. Attention에는 근거가 약한 결정처럼 더 자세히 볼 만한 항목이 정리돼 있어요. 그 로그 줄을 따라가며 확인하세요.

<Term k="决策日志" />는 기본적으로 작업 폴더의 `decisions.tsv` 파일이에요. 커밋되지는 않아요. 각 행이 결정 하나이고, 이유와 근거가 함께 적혀 있어요.

현재 상태만 빠르게 보고 싶나요? 실행 중인 대화에 `/ketchup`을 입력하세요. 읽기만 해요. 뭐가 바뀌었고, 어떤 결정이 기다리고 있는지 알려 줘요.

## 중간에 멈추기

노트북을 덮거나 에디터를 다시 시작해야 하면 “잠시 멈춰 주세요” 또는 “이제 자리 비울게요”라고 말하세요. 저장하지 않은 작업을 `wip:` 커밋으로 남기고, 나중에 이어서 할 메모를 적어 둬요. 새 대화를 열어 이어받게 하세요. 메모를 보고 이어서 작업해요.

“계속해 주세요”나 “이어서 해 주세요”라고 말해도 멈추지 않아요.

## 밤새 할 일이 여러 개일 때

서로 관련 없는 변경이 여러 개 이어질 때 쓰는 <Term k="剧本" text="플레이북" />이 두 가지 있어요:

- **Autopilot-stack: 머지하지 않아요**. 아침에 검증된 PR을 보고 직접 결정해요.
- **Autopilot-full: 머지해요**. 다른 도우미 AI가 검증한 뒤에만 각 PR을 머지해요.

며칠씩 걸리는 프로젝트에는 따로 정해진 플레이북이 없어요. `/poteto-mode`가 `/figure-it-out`에 넘기면, 그 자리에서 접근 방식을 설계해요.

잘 모르겠다면 Autopilot-stack을 고르세요. 머지하기 전에 직접 최종 결정할 수 있어요.
