## Установите pstack

Введите эти две строки одну за другой в поле чата Claude Code:

<Copy id="cc-plugin" title="Установка из магазина плагинов" code={`/plugin marketplace add cursor/plugins
/plugin install pstack@cursor-plugins`} />

Так установится полный набор, и у `/poteto-mode` будет всё необходимое. Если сомневаетесь — выберите этот вариант.

**Чтобы выбрать навыки самостоятельно**, введите в терминале (не в поле чата):

<Cmd c="npx skills add backnotprop/pstack" />

Отметьте нужные навыки и выберите Claude Code в качестве инструмента. Навыки установятся в `.claude/skills/`. Какие именно выбрать, смотрите в руководстве [Установить только несколько навыков](/ru/howto/pick-skills/).

## Добавляйте pstack: перед командами

Если вы устанавливали pstack из магазина плагинов, все команды находятся под именем плагина. Обычная команда `!/poteto-mode` не распознаётся — вводите:

<Cmd c="!/pstack:poteto-mode" />

То же касается и других команд, например `!/pstack:how`. Таково правило Claude Code для плагинов, чтобы два плагина не конфликтовали из-за одинаковых имён. При установке через `npx skills` префикса нет.

Команды на этом сайте по умолчанию указаны для плагина, чтобы их можно было просто скопировать. Если вы ставили через `npx skills`, выберите здесь «Установлено через npx»:

<ToolPick />

<Callout type="warn" title="Навыки не запускаются сами">
Кроме `setup-pstack`, любой навык запускается только тогда, когда вы сами вводите его команду. Фраза «помоги исправить баг» не включит `/pstack:poteto-mode`.
</Callout>

## Выберите модели и начните новую сессию

После установки выполните один раз:

<Cmd c="/pstack:setup-pstack" />

Команда спрашивает про ваш <Term k="推理预算" /> (как долго модели думают), а затем назначает модель на каждую <Term k="模型角色" />. В итоге она записывает один файл: `~/.claude/rules/pstack-models.md`.

Claude Code читает файлы `.md` в этой папке каждый раз при запуске новой сессии. Поэтому <mark>после настройки выйдите и откройте новую сессию, прежде чем начинать работу</mark>. В текущей сессии всё ещё действуют старые настройки.

Модель записывается в формате «имя + уровень», например `opus xhigh`. Поддерживаются только имена `opus`, `sonnet`, `haiku` и `fable`. Держите эти строки только в этом файле. Не копируйте их в `CLAUDE.md`.

## Как лучше настроить

**Большинству подойдёт план «Сбалансированный»**: сессия работает на opus, а код пишет sonnet.

Почему так? Выбор моделей зависит от двух вещей:

- **Модель сессии**: та, которую вы выбираете через `/model`, — ИИ, с которым вы общаетесь напрямую. Он выбирает подход, распределяет задачи и проверяет каждое изменение.
- **Строки в файле настроек**: на какой модели работает каждый ИИ-помощник (<Term k="子代理" text="субагент" />).

По умолчанию pstack использует opus 5.5 для написания кода и принятия решений. В коллегию ревью (где одно изменение проверяют сразу несколько моделей) входят по одной модели fable, opus и gemini. Claude Code не умеет работать с gemini, поэтому это место получает `inherit-parent`. Это значит «следовать за моделью сессии».

Если ничего не менять, почти всю работу делает opus, а это самый дорогой вариант. План «Сбалансированный» переносит написание кода на sonnet, что снижает расходы вдвое. Кроме того, третье место в коллегии ревью тоже получает sonnet, и все три места занимают разные модели.

Цены — по базовому тарифу API на октябрь 2026 года за миллион <Term k="token" text="токенов" />. На подписке более дорогие модели быстрее расходуют лимиты:

| Модель | Вход / выход | Для чего подходит |
| --- | --- | --- |
| fable | $10 / $50 | Самая сильная, по умолчанию в коллегии ревью |
| opus | $4 / $20 | Сессия, принятие решений, тексты |
| sonnet | $2 / $10 | Написание кода, одно место в коллегии ревью |
| haiku | $0.1 / $0.5 | Не рекомендуется |

Почему не haiku: проверка результатов использует модель из `swarm workers`. Поставите туда самую дешёвую модель — и проверки тоже станут слабее.

### Три плана

<Tabs id="cc-plans" label="Выберите план" items={[["balanced", "Сбалансированный (рекомендуется)"], ["cheap", "Экономный"], ["max", "Цена не важна"]]}>
<div slot="balanced">

**Сессия работает на opus, код и проверки отдаются sonnet, а на каждом ревью сидят fable, opus и sonnet.**

Сессии нужно понимать вас и проверять изменения, поэтому ей достаётся opus. ИИ-помощники для написания кода получают чётко очерченные задачи, с которыми sonnet справляется. Принятие решений и тексты остаются на opus.

<Copy id="cc-plan-balanced" title="~/.claude/rules/pstack-models.md (сбалансированный)" code={`# pstack model configuration. One line per role. Delete a line to fall back to the skill default.
# defaults: 3
# budget: large (xhigh)
feature, refactoring: sonnet xhigh
bug-fix: sonnet xhigh
perf-issue: sonnet xhigh
hillclimb: sonnet xhigh
judgment and prose: opus xhigh
arena runners: fable high, opus high, sonnet high
arena cross-judge pool: opus high, inherit-parent
swarm workers: sonnet high
interrogate reviewers: fable high, opus high, sonnet high`} />

</div>
<div slot="cheap">

**Сессия работает на sonnet, в строках для кода стоит `inherit-parent`, выбран бюджет `medium`.**

`inherit-parent` следует за сессией на sonnet, а решения по-прежнему принимает opus. Бюджет `medium` понижает каждую роль на один уровень: `xhigh` становится `high`, а `high` у ревьюеров — `medium`. Из коллегии ревью убирается fable, остаются два места. Перед сложной задачей переключитесь обратно на opus через `/model`.

<Copy id="cc-plan-cheap" title="~/.claude/rules/pstack-models.md (экономный)" code={`# pstack model configuration. One line per role. Delete a line to fall back to the skill default.
# defaults: 3
# budget: medium (high)
feature, refactoring: inherit-parent
bug-fix: inherit-parent
perf-issue: inherit-parent
hillclimb: inherit-parent
judgment and prose: opus high
arena runners: opus medium, inherit-parent
arena cross-judge pool: opus medium, inherit-parent
swarm workers: inherit-parent
interrogate reviewers: opus medium, inherit-parent`} />

</div>
<div slot="max">

**Сессия работает на opus, код, решения и проверки тоже на opus, а все три места в коллегии ревью работают на `xhigh`.**

Почему бы не отдать принятие решений модели fable? В pstack действует правило: вне коллегии ревью модель fable запускается только когда вы явно называете её, либо после того, как opus дважды не справится с одной и той же задачей. Чтобы задействовать её для одной задачи, напишите в промпте «используй fable для этой задачи». Базовая цена fable в 2,5 раза выше, чем у opus. Если в вашем аккаунте нет доступа к fable, настройка её не предложит.

<Copy id="cc-plan-max" title="~/.claude/rules/pstack-models.md (цена не важна)" code={`# pstack model configuration. One line per role. Delete a line to fall back to the skill default.
# defaults: 3
# budget: large (xhigh)
feature, refactoring: opus xhigh
bug-fix: opus xhigh
perf-issue: opus xhigh
hillclimb: opus xhigh
judgment and prose: opus xhigh
arena runners: fable xhigh, opus xhigh, sonnet xhigh
arena cross-judge pool: opus high, inherit-parent
swarm workers: opus xhigh
interrogate reviewers: fable xhigh, opus xhigh, sonnet xhigh`} />

</div>
</Tabs>

`large` — это максимальный бюджет: ни одна роль в pstack не работает выше уровня `xhigh`. Оставьте в файле строку `# defaults: 3`. Без неё pstack решит, что файл создан старой версией, и попросит запустить настройку заново.

### Как записать настройки

1. Выберите модель сессии с помощью `/model`.
2. Запустите `/pstack:setup-pstack` и выберите бюджет для вашего плана.
3. Когда команда спросит, нужно ли изменить какие-то роли, вставьте содержимое файла выше и попросите записать именно его.
4. Выйдите и начните новую сессию.

## Вы видите «Skipped in Claude Code»

В Claude Code нет запланированных задач Cursor, бота для ревью Bugbot и облачных агентов. Шаги, которые их используют, пропускаются. В ответ добавляется одна строка, и работа идёт дальше:

<Copy id="cc-skip" title="Вы увидите примерно такую строку" code="Skipped in Claude Code: <какой шаг>. <почему он пропущен>." />

Открывать <Term k="PR" /> (Pull Request — запрос на проверку и слияние изменений) по-прежнему можно — для этого используется `gh pr create`. Команда `/loop` здесь тоже есть. Если ИИ пишет, что оставил заглушку (например, на месте недостающей ссылки), проверьте, чего не хватает, и при необходимости заполните.

## Включите автообновление

По умолчанию Claude Code не обновляет сторонние плагины. Чтобы включить автообновление:

1. Введите `/plugin` в поле чата.
2. Откройте вкладку **marketplaces**.
3. Выберите `cursor-plugins`.
4. Нажмите **enable auto-update**.

Чтобы обновить плагин вручную, выполните в терминале:

<Cmd c="claude plugin update pstack@cursor-plugins" />

Если обновление меняет модели по умолчанию, в вашем старом файле настроек останутся прежние. Как это исправить, смотрите в разделе [Обновление, проверка и удаление](/ru/howto/update-remove/).

## Удаление или пауза

Введите в поле чата:

<Cmd c="/plugin uninstall pstack@cursor-plugins" />

Затем введите `/reload-plugins` или перезапустите Claude Code. Чтобы временно отключить плагин, замените `uninstall` на `disable`, а чтобы снова включить — используйте `enable`. Если вы запускали настройку, после удаления также удалите `~/.claude/rules/pstack-models.md`, иначе каждая новая сессия продолжит его читать.

## Застряли?

<Q q="Ввожу команду — ничего не происходит, и в меню её нет.">
Если вы устанавливали pstack из магазина плагинов, вводите `!/pstack:poteto-mode`: без `pstack:` команда не распознаётся. Начните вводить `/pstack:`, и в меню останутся только команды pstack.
</Q>
<Q q="После настройки выбранные модели не применились.">
Файл настроек читается только при запуске новой сессии. Выйдите и откройте новую. Если это не помогло, откройте `~/.claude/rules/pstack-models.md` и проверьте, что в нужной строке указана выбранная вами модель.
</Q>
<Q q="В ответе сказано, что /arena пропустила судью или не нашла ревьюера от другой компании.">
Нескольким шагам для проверки нужна модель от «другой компании», например судье в `/arena`. Все модели Claude, включая fable, считаются моделями одной компании. Поэтому ИИ пропускает судью, выбирает сам себя и сообщает об этом. Строка `arena cross-judge pool` здесь почти ни на что не влияет. Если для важного ревью нужен взгляд модели другой компании, перенесите такое ревью в Codex или Cursor и запустите там `/interrogate`.
</Q>
<Q q="В навыках используются названия из Cursor. Нужно ли их переводить?">
Нет. В плагине есть таблица соответствий (`docs/harness/claude-code.md`), и ИИ переводит их сам. Например, `.cursor/rules/` превращается в `CLAUDE.md` (или `AGENTS.md`, если его нет), а облачные агенты — в локальный <Term k="worktree" /> (отдельная рабочая папка того же Git-репозитория).
</Q>
<Q q="ИИ пишет, что инструмент Skill не может вызвать навыки pstack. Что-то сломалось?">
Нет. В Claude Code большинство навыков pstack нельзя вызвать таким способом. ИИ читает `SKILL.md` нужного навыка напрямую и следует ему. Продолжайте вводить команды как обычно.
</Q>
<Q q="Ночной запуск застрял на запросе разрешения.">
Прежде чем оставить ИИ работать самостоятельно, разрешите частые команды: git, gh, а также ваши команды для тестов и сборки. Встроенная команда Claude Code `/fewer-permission-prompts` находит часто используемые команды только для чтения и записывает их в `.claude/settings.json` проекта. Разрешать ли команды, которые что-то меняют, — ваш выбор.
</Q>
